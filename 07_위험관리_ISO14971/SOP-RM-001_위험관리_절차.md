# SOP-RM-001 위험관리 절차 v0.3

## 1. 목적

본 절차는 의료용 X-ray 시스템(detector·SW 포함)의 구상 단계부터 폐기까지 전주기에 걸친 위험관리 프로세스를 정의한다. ISO 14971:2019 요구사항을 충족하고, EU MDR Annex I 일반 안전·성능 요구사항(GSPR) 및 FDA QMSR 위험 기반 접근법에 부합하는 것을 목표로 한다.

## 2. 적용 범위

- 의료기기 하드웨어(X-ray tube, generator, collimator, detector assembly)
- 내장 소프트웨어(영상 획득·처리·표시, DICOM 통신, 사이버보안 모듈)
- AI/ML 구성요소(영상 전처리, 자동 노출 제어, 화질 최적화)
- 부속품·소모품(grid, 환자 포지셔닝 보조기구)
- 서비스 활동(설치, PM, 교정, 해체)

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 위해(Hazard) | 잠재적 피해 원인 |
| 위해상황(Hazardous Situation) | 사람·재산·환경이 위해에 노출되는 상황 |
| 피해(Harm) | 사람의 건강에 대한 상해 또는 손상 |
| 심각도(Severity) | 피해의 심각한 정도 |
| 발생확률(Probability of Occurrence) | 위해상황이 피해로 이어질 확률 |
| 위험(Risk) | 피해의 심각도와 발생확률의 조합 |
| 잔여위험(Residual Risk) | 위험 통제 수단 적용 후 남은 위험 |
| ALARP | As Low As Reasonably Practicable |
| TPLC | Total Product Life Cycle — FDA CP 7382.850 기반 전제품수명주기 접근법 |

## 4. 책임과 권한

| 역할 | 책임 |
|------|------|
| 경영대표 | 위험관리 방침 승인, 자원 배분, 잔여위험 수용 최종 결정 |
| RA/QA Lead | 위험관리 파일(RMF) 총괄, 위험 평가·통제 조율, QMSR 실사 대응 |
| 설계팀 | 위해 식별, FMEA·FTA 수행, 위험 통제 수단 설계·구현 |

| 임상/규제 | 임상 benefit-risk 분석, 규제기관 보고 |

## 5. 절차

### 5.1 위험관리 계획 (Risk Management Plan)

위험관리 계획서(F-RM-001)에는 다음 사항을 포함한다.

1. 적용 범위 — 대상 의료기기·수명주기 단계
2. 책임·권한 배분
3. 위험 수용 기준(Acceptability Criteria)
4. 검증 활동 계획
5. 생산·시판 후 정보 수집 방법
6. 위험관리 활동 시기·검토 주기

**위험 수용 매트릭스:**

| 심각도 \ 확률 | 빈번(5) | 때때로(4) | 가끔(3) | 드묾(2) | 극히 드묾(1) |
|---|---|---|---|---|---|
| 치명적(5) | 불허 | 불허 | 불허 | ALARP | ALARP |
| 중대(4) | 불허 | 불허 | ALARP | ALARP | 수용 |
| 보통(3) | 불허 | ALARP | ALARP | 수용 | 수용 |
| 경미(2) | ALARP | ALARP | 수용 | 수용 | 수용 |
| 무시(1) | ALARP | 수용 | 수용 | 수용 | 수용 |

### 5.2 위해 식별 (Hazard Identification)

사용 시나리오·사용 오류·장애 모드·환경 조건·사이버 위협별로 위해를 식별한다. X-ray 시스템 특유 위해 범주:

- 방사선 과다 노출(tube output 초과, AEC 오작동, collimator 오정렬)
- 영상 품질 저하(detector defect pixel, gain drift → 오진)
- 전기적 위험(고전압 회로, 접지 결함)
- 기계적 위험(갠트리 충돌, 환자 낙상)
- SW 오동작(영상 좌우 반전, 환자 ID 불일치, DICOM 전송 실패)
- AI/ML 오류(drift에 의한 노출 파라미터 오산출, 편향)
- 사이버보안(랜섬웨어에 의한 가용성 상실, 환자정보 유출)
- 사용 오류(IEC 62366-1 연계)

#### 5.2.1 사용 오류 위해 식별 세부 절차 (IEC 62366-1:2015+A1:2020 연계)

사용 오류(Use Error)로 인한 위해를 체계적으로 식별하기 위해 사용적합성 공학(Usability Engineering) 프로세스와 연계하여 다음 절차를 수행한다.

**Task Analysis → Use Error → Hazardous Situation 연결 프로세스:**

1. **사용 시나리오 정의:** 의도된 사용 환경·사용자 프로파일·사용 조건을 정의하고, 주요 사용 과업(Task)을 목록화한다.
2. **Task Analysis 수행:** 각 사용 과업을 세부 단계(Sub-task)로 분해하고, 단계별 사용자-기기 상호작용을 분석한다.
3. **사용 오류 식별:** 각 세부 단계에서 발생 가능한 사용 오류를 식별한다. 유형은 다음을 포함한다:
   - 인지 오류(Perception Error): 정보 인식 실패(예: 경고 표시 미인지)
   - 판단 오류(Cognition Error): 정보 해석 오류(예: 파라미터 의미 오해)
   - 실행 오류(Action Error): 의도한 조작의 실패(예: 버튼 오조작, 순서 착오)
   - 기억 오류(Memory Error): 절차·설정값 망각
4. **위해상황 연결:** 식별된 사용 오류가 유발하는 위해상황(Hazardous Situation)을 매핑한다. 동일 사용 오류가 복수의 위해상황으로 이어질 수 있음을 고려한다.
5. **피해 추정:** 각 위해상황에서 발생 가능한 피해(Harm)의 심각도를 추정한다.

**기록:** 사용 오류 위해 식별 결과는 F-RM-002 위험분석 워크시트에 통합 기록하며, 사용적합성 엔지니어링 파일(Usability Engineering File)과 상호 참조한다.

### 5.3 위험 분석 (Risk Analysis)

식별된 위해별로 위해상황·피해·심각도·발생확률을 분석하여 위험을 추정한다.

**분석 기법:**
- **FMEA (Failure Mode and Effects Analysis):** 구성요소·기능별 고장 모드, 원인, 영향, RPN 산출
- **FTA (Fault Tree Analysis):** 최상위 사건(Top Event: 환자 과다 피폭 등)에서 역추적
- **HAZOP:** 공정·사용 시나리오 체계적 편차 분석
- **위협 모델링(Threat Modeling):** STRIDE/DREAD 기반 사이버보안 위해 분석

기록 양식: F-RM-002 위험분석 워크시트

> **참고 — Bayesian 기법을 활용한 발생확률 추정 (ISO/TR 24971:2020 Annex C 참조)**
>
> 시판 전 임상 데이터가 제한적인 경우, Bayesian 통계 기법을 활용하여 발생확률을 추정할 수 있다.
> - **사전 확률(Prior):** 유사 의료기기 시판 후 데이터, 문헌 데이터, 전문가 판단(Delphi법 등)에서 도출한다.
> - **우도(Likelihood):** 시험·검증 데이터, 불만 데이터, 시뮬레이션 결과 등 관측 데이터를 반영한다.
> - **사후 확률(Posterior):** 사전 확률과 우도를 결합하여 갱신된 발생확률을 산출한다.
> - 발생확률 등급 배정 시 사후 분포의 중앙값 또는 95% 신뢰구간 상한(Upper Credible Limit)을 활용하여 보수적으로 판정할 수 있다.
> - Bayesian 기법 적용 시 사전 확률의 근거·가정·민감도 분석 결과를 F-RM-002에 문서화한다.

### 5.4 위험 평가 (Risk Evaluation)

5.1항의 수용 기준 매트릭스 대비 각 위험을 판정한다.
- **불허(Unacceptable):** 반드시 위험 통제 필요
- **ALARP:** 실현 가능한 한 위험 저감 후 benefit-risk 분석으로 수용 여부 결정
- **수용(Acceptable):** 현 수준 유지, 모니터링

### 5.5 위험 통제 (Risk Control)

위험 통제 수단의 우선순위(ISO 14971 §7.1):
1. **본질적 안전 설계(Inherent Safety by Design):** 위해 자체 제거·감소
2. **보호 수단(Protective Measures):** 경보, 인터록, 차폐, SW safety function
3. **안전성 정보(Information for Safety):** 경고 라벨, 사용설명서, 교육

각 통제 수단의 구현·검증을 기록하고, 신규 위해 도입 여부를 확인한다.

**X-ray 특수 통제 예시:**
- AEC 최대 노출 시간 HW 인터록
- 투시(Fluoroscopy) 5분 경보, 10분 강제 차단
- Collimator 자동 추종 실패 시 노출 차단
- Detector 결함 pixel > 임계치 시 영상 획득 중단 + 경고

#### SW Safety Classification에 따른 위험 통제 차등 적용 (IEC 62304 연계)

소프트웨어 안전 분류(SW Safety Class)에 따라 위험 통제 수단의 엄격도를 차등 적용한다. 아래 매핑 테이블은 IEC 62304:2006+A1:2015의 SW Safety Class 정의에 기반한다.

| 항목 | Class A (기여 없음) | Class B (비중대 상해 기여) | Class C (사망·중대 상해 기여) |
|------|---------------------|---------------------------|-------------------------------|
| **위험 통제 수단 범위** | 기본 SW 개발 프로세스 | 검증 강화, 코드 리뷰 필수 | 최대 엄격도, 정형 검증 권고 |
| **단위 시험 커버리지** | 권장 | 문장(Statement) 커버리지 ≥80% | 분기(Branch) 커버리지 ≥90%, MC/DC 권고 |
| **통합 시험** | 기본 기능 확인 | 인터페이스 시험 필수 | 결함 주입(Fault Injection) 시험 포함 |
| **아키텍처 문서화** | 선택 | 필수 — 모듈 간 인터페이스 명세 | 필수 — 안전 관련 요소 분리(Partitioning) 입증 |
| **이상 탐지·방어 코딩** | 선택 | 입력 검증, 오류 처리 | 방어 코딩 필수, Watchdog, 이중화(Redundancy) |
| **형상관리·추적성** | 기본 | 요구사항→코드→시험 추적 | 양방향 추적성 필수, 변경 영향 분석 |
| **위험 통제 검증** | 기능 시험 | 기능 시험 + 리그레션 | 기능 시험 + 리그레션 + 침투 시험(Class C 보안 관련 SW) |

> **적용 지침:** SW Safety Class 배정은 SW 항목이 위해상황에 기여하는 정도에 따라 결정하며, 위험관리 프로세스(본 절차 §5.2~5.4)의 결과를 입력으로 사용한다. Class 배정 결과 및 근거는 위험관리 파일에 기록한다.

### 5.6 잔여위험 평가 (Residual Risk Evaluation)

모든 통제 수단 적용 후 개별 잔여위험 및 전체(Overall) 잔여위험을 평가한다.
- 전체 잔여위험이 수용 불가 시 benefit-risk 분석 수행
- 잔여위험 정보를 부속문서(IFU)에 반영

### 5.7 위험관리 검토 (Risk Management Review)

위험관리 파일의 완결성을 검토한다:
- 위험관리 계획이 적절히 이행되었는가
- 전체 잔여위험이 수용 가능한가
- 생산·시판 후 정보 수집 방법이 적절한가

검토 결과를 경영대표에게 보고, 승인을 득한다.

### 5.8 생산 및 시판 후 활동 (Production & Post-Production)

- PMS 데이터(불만, FSCA, PSUR)에서 신규 위해 또는 위험 변동 정보 수집
- 변경 발생 시 SOP-CC-001에 따라 위험 재평가
- AI/ML 모델 업데이트 시 성능 drift 재평가
- 수집 정보를 위험관리 파일에 피드백

#### 5.8.1 시판 후 위험관리 활동 구체화

**PMS 데이터 환류 주기 및 절차:**

1. **데이터 수집(상시):** 다음 소스에서 위험 관련 데이터를 지속 수집한다.
   - 고객 불만(Complaint) — SOP-PMS-001에 따라 접수·분류
   - 부작용 보고(Adverse Event Report) — 중대 부작용 발생 시 즉시 보고
   - FSCA(Field Safety Corrective Action) — 자사 및 유사기기 FSCA 정보
   - PSUR/PMSR 작성 데이터
   - 규제기관 안전성 경보(예: MFDS 안전성 정보, FDA MAUDE, EU EUDAMED)
   - EUDAMED Market Surveillance 모듈 데이터(2026-05-28 의무화)
2. **분기별 위험관리 파일 환류 검토:**
   - 매 분기 종료 후 15영업일 이내에 RA/QA Lead 주관으로 PMS 데이터를 취합·검토한다.
   - 신규 위해 또는 기존 위험의 심각도·발생확률 변동 여부를 판정한다.
   - 변동이 확인된 경우 F-RM-002를 갱신하고, 필요 시 추가 통제 수단을 수립한다.
   - 검토 결과를 위험관리 파일에 첨부하고, 경영대표에게 보고한다.
3. **트렌드 분석 기준:**
   - **발생률 트렌드:** 이동평균(3개 분기) 대비 당 분기 불만·부작용 발생 건수를 비교한다.
   - **통계적 유의성 판단:** 이항 검정(Binomial Test) 또는 포아송 검정(Poisson Test)을 활용하여 발생률 변동의 통계적 유의성(p < 0.05)을 판정한다.
   - **시그널 탈지(Signal Detection):** 비례보고비(PRR, Proportional Reporting Ratio) ≥ 2 이고 Chi-square ≥ 4인 경우 안전성 시그널로 분류하여 심층 조사를 개시한다.
   - 트렌드 분석 결과 및 판정 근거는 분기별 환류 검토 기록에 문서화한다.

### 5.9 사이버보안 위협 분석 (Threat Modeling)

의료기기 소프트웨어의 사이버보안 위협을 체계적으로 식별·분석하기 위해 IEC 81001-5-1:2021 §5.3~5.5를 준수하여 다음 절차를 수행한다.

#### 5.9.1 위협 모델링 범위 및 시점

- **범위:** 네트워크 연결 인터페이스(DICOM, HL7 FHIR, Wi-Fi, Ethernet), 데이터 저장소(환자 정보, 구성 파일), 원격 서비스 포트, SW 업데이트 메커니즘을 포함한다.
- **시점:** 설계 입력 단계에서 초기 위협 모델을 수립하고, 설계 변경·아키텍처 변경·신규 인터페이스 추가 시 갱신한다.

#### 5.9.2 STRIDE 위협 분류 모델

각 자산·인터페이스에 대해 STRIDE 모델로 위협을 분류한다.

| STRIDE 범주 | 설명 | X-ray 시스템 위협 예시 |
|-------------|------|------------------------|
| **S**poofing (위장) | 신원 위조 | 비인가 사용자가 관리자 세션 탈취 |
| **T**ampering (변조) | 데이터 무결성 침해 | 영상 데이터·선량 파라미터 변조 |
| **R**epudiation (부인) | 행위 부인 | 노출 파라미터 변경 이력 삭제 |
| **I**nformation Disclosure (정보 유출) | 기밀성 침해 | 환자 DICOM 데이터 비인가 접근 |
| **D**enial of Service (서비스 거부) | 가용성 침해 | 랜섬웨어에 의한 영상 획득 불가 |
| **E**levation of Privilege (권한 상승) | 권한 무단 획득 | 일반 사용자가 서비스 모드 진입 |

#### 5.9.3 CVSS 기반 위험 등급화

식별된 위협별로 CVSS(Common Vulnerability Scoring System) v3.1 기본 점수를 산출하여 위험을 등급화한다.

| CVSS 점수 범위 | 위험 등급 | 위험관리 대응 |
|---------------|-----------|---------------|
| 9.0 – 10.0 | Critical | 즉시 통제 수단 수립·구현, 출시 차단 조건 |
| 7.0 – 8.9 | High | 출시 전 통제 수단 구현 필수 |
| 4.0 – 6.9 | Medium | 통제 수단 수립, benefit-risk 기반 출시 판정 가능 |
| 0.1 – 3.9 | Low | 모니터링 및 차기 릴리스 반영 |

#### 5.9.4 사이버보안 위험 통제 수단 예시

- 인증·접근 통제: 역할 기반 접근 제어(RBAC), 다중 인증(MFA)
- 데이터 보호: 전송 암호화(TLS 1.2+), 저장 암호화(AES-256)
- 무결성 보장: 디지털 서명, Secure Boot, SW 업데이트 무결성 검증
- 감사 추적: 보안 이벤트 로깅, 변경 불가 감사 로그
- 네트워크 방어: 방화벽 규칙, 불필요 포트·서비스 비활성화

#### 5.9.5 IEC 81001-5-1 참조 매핑

| 본 절차 항목 | IEC 81001-5-1:2021 조항 |
|-------------|------------------------|
| 5.9.1 범위 | §5.3 보안 요구사항 분석 |
| 5.9.2 STRIDE | §5.4 위협 모델링 |
| 5.9.3 CVSS 등급화 | §5.4 위협 모델링 — 위험 산정 |
| 5.9.4 통제 수단 | §5.5 보안 설계·구현 |
| 5.9.5 참조 매핑 | §5.3~5.5 통합 |

**기록:** 사이버보안 위협 분석 결과는 F-RM-002에 통합 기록하며, 사이버보안 관리 파일(Cybersecurity Management File)과 상호 참조한다.

### 5.10 FDA QMSR / CP 7382.850 위험관리 실사 대응 (v0.3 신설)

#### 5.10.1 QMSR 하 위험관리의 위치

FDA QMSR(2026-02-02 발효)은 ISO 13485:2016을 참조편입하며, ISO 14971을 직접 편입하지는 않으나 ISO 13485 §7.1이 위험관리 프로세스 수립을 요구한다. CP 7382.850 실사 매뉴얼은 위험관리를 QMS 전체를 관통하는 "척추(Spine)"로 규정하며, 2026년 2~3월 초기 QMSR 실사에서 위험관리가 가장 많은 Form 483 관찰사항으로 기록되었다.

**CP 7382.850 실사 목표 2단계:**
1. 제조자의 QMS가 FDA 요구사항을 충족하고 기기의 안전성·유효성에 합리적 보증을 제공하는지 평가
2. 위험관리 및 위험 기반 의사결정이 QMS 전반에 효과적으로 활용되는지 평가

#### 5.10.2 CP 7382.850 6대 QMS 영역별 위험관리 통합

CP 7382.850은 실사 대상을 6개 QMS 영역으로 조직하며, 각 영역에서 위험관리 연계를 확인한다.

| CP 7382.850 QMS 영역 | 위험관리 연계 항목 | 본 절차/관련 문서 참조 |
|---------------------|-------------------|---------------------|
| **변경통제(Change Control)** | 변경이 위험에 미치는 영향 평가, 위험 재평가 근거 | §5.8, SOP-CC-001 |
| **설계개발(Design & Development)** | 설계 입력에 위험관리 계획 포함, 설계 검증·확인에 위험 통제 효과성 확인 | §5.1~5.7 |
| **경영감독(Management Oversight)** | 위험관리 방침·자원 배분, 잔여위험 수용 승인 | §4, §5.7 |
| **측정·분석·개선(MAI)** | PMS 데이터 기반 위험 트렌드 분석, CAPA와 위험 재평가 연계 | §5.8.1, PRO-DA-001 |
| **외주·구매(Outsourcing & Purchasing)** | 공급자 위험 평가, 외주 공정의 위험 통제 | SOP-SUP-001 |
| **생산·서비스(Production & Service)** | 공정 위험 통제, 서비스 활동의 위험 영향 | SOP-MFG-001, SOP-SVC-001 |

#### 5.10.3 QMSR 실사 대비 위험관리 파일 자가점검표

실사 전 RA/QA Lead는 아래 자가점검을 수행하고 결과를 위험관리 파일에 첨부한다.

| # | 점검 항목 | 근거 조항 | 적합/부적합 |
|---|----------|----------|------------|

| 2 | 위험관리 계획에 수용 기준, 검증 활동, 시판 후 정보 수집 방법이 포함되어 있는가? | ISO 14971 §4.4 | |
| 3 | 위험 분석 기록에 위해·위해상황·피해·심각도·발생확률이 문서화되어 있는가? | ISO 14971 §5 | |
| 4 | 위험 통제 수단별 구현·검증 기록이 존재하고, 통제 효과성이 입증되어 있는가? | ISO 14971 §7 | |

| 7 | 설계변경·공정변경 시 위험 재평가가 수행되었는가? | ISO 13485 §7.3.9, CP 7382.850 CC | |
| 8 | 공급자 관련 위험이 식별·평가되어 있는가? | CP 7382.850 O&P | |

| 10 | 사이버보안 위협이 위험관리 파일에 통합되어 있는가? | FDA Cybersecurity Guidance, IEC 81001-5-1 | |

#### 5.10.4 OAI(Official Action Indicated) 방지 핵심 사항

CP 7382.850은 아래 위험관리 결함 발견 시 실사를 OAI로 분류할 수 있음을 명시한다:

- 제품 실현에서 위험관리 프로세스 미수립·미이행·미유지
- 위험 통제 수단의 효과성 미검증
- 시판 후 정보의 위험관리 파일 미환류

이를 방지하기 위해 RA/QA Lead는 §5.10.3 자가점검을 최소 반기 1회 수행하고, 부적합 발견 시 즉시 시정 조치를 취한다.

### 5.11 EUDAMED 연계 위험 데이터 관리 (v0.3 신설)

#### 5.11.1 EUDAMED Market Surveillance 모듈 연동

2026-05-28 EUDAMED 4개 모듈 의무화에 따라, Market Surveillance 모듈에서 규제당국이 게시하는 안전성 조치 정보를 위험관리 활동에 활용한다.

- **모니터링 대상**: EUDAMED에 등록된 유사기기(X-ray, digital detector, imaging SW)의 안전성 시정조치(FSCA) 정보
- **모니터링 주기**: 월 1회 이상
- **위험관리 파일 반영**: 유사기기 FSCA에서 자사 기기에 적용 가능한 위해가 확인된 경우, F-RM-002를 갱신하고 해당 위해의 발생확률을 재평가한다.

#### 5.11.2 EUDAMED Vigilance 모듈 과도기 대응

EUDAMED Vigilance 모듈은 아직 의무화되지 않았으며, 2027년 Q2경 의무화가 예상된다. 과도기 동안:

- 중대 사고(Serious Incident) 보고는 각국 CA에 직접 보고 유지
- MIR form v7.3.1 사용(2026-05 의무)
- Vigilance 모듈 의무화 확정 시 위험 데이터 수집 채널에 EUDAMED Vigilance를 추가하고, 위험관리 계획(F-RM-001)을 갱신한다.
