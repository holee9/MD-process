# SOP-CAPA-001 — 시정조치 및 예방조치 절차 (CAPA Procedure)

> **문서번호**: SOP-CAPA-001 | **버전**: v0.1 (초안) | **시행일**: TBD  
> **작성**: QA | **검토**: RA, 설계, 생산 | **승인**: QA장

---

## 1. 목적

제품 실현 전 과정에서 발생하는 부적합(Nonconformity), 고객 불만(Complaint), 내·외부 감사 지적(Audit Finding), 경향 분석 결과(Trend) 등의 근본 원인을 체계적으로 조사하고, 시정조치(Corrective Action) 및 예방조치(Preventive Action)를 수립·이행·효과 검증하여 재발 방지 및 잠재 부적합 예방을 달성한다.

## 2. 적용 범위

- 자사 제조 의료용 X-ray 시스템, 디지털 디텍터(FPD), 영상처리 SW(AI 포함)
- QMS 전 프로세스(설계, 제조, 검사, 공급자 관리, PMS, 문서관리, 교육 등)
- 전 시장(국내 MFDS, 미국 FDA, EU/NB)

## 3. 관련 규제·표준

| 규제/표준 | 조항 | 핵심 요구사항 |
|-----------|------|---------------|
| ISO 13485:2016 | §8.5.2 | 시정조치: 부적합 원인 제거, 재발 방지 |
| ISO 13485:2016 | §8.5.3 | 예방조치: 잠재 부적합 원인 제거 |
| ISO 13485:2016 | §8.3 | 부적합 제품 관리 |
| FDA QMSR | 21 CFR 820 → ISO 13485 | CAPA 절차·기록 유지 |
| EU MDR 2017/745 | Art.10(12), Annex IX §3.3 | 시정조치 체계, 인증기관 보고 |
| MFDS GMP 기준 | 별표2 제5장 | 시정·예방조치 |
| ISO 14971:2019 | §10 | 생산·생산후 정보 → 위험관리 환류 |

## 4. 용어 정의

| 용어 | 정의 |
|------|------|
| **시정(Correction)** | 검출된 부적합을 제거하는 즉각적 조치 (예: 불량품 격리·재작업) |
| **시정조치(Corrective Action, CA)** | 부적합의 근본 원인을 제거하여 **재발을 방지**하는 조치 |
| **예방조치(Preventive Action, PA)** | 잠재적 부적합의 원인을 제거하여 **발생을 예방**하는 조치 |
| **부적합(Nonconformity)** | 요구사항의 불충족 |
| **근본 원인(Root Cause)** | 부적합을 야기한 가장 근본적인 원인 요소 |
| **효과 검증(Effectiveness Verification)** | 시정·예방조치가 목적을 달성했는지 객관적으로 확인하는 활동 |
| **CAPA Board** | CAPA 심의·우선순위·종결 판정 위원회 |

## 5. 책임과 권한

| 역할 | 책임 |
|------|------|
| **CAPA 개시자** | CAPA 요청서(F-CAPA-001) 작성, 즉시 시정 실행 |
| **QA 담당** | CAPA 접수·분류·등록, 진행 모니터링, 기한 관리 |
| **CAPA 조사 책임자** | 근본 원인 분석, 시정·예방조치 계획 수립, 이행 |
| **CAPA Board** | 중등도 이상 CAPA 심의, 조치 계획 승인, 종결 판정 |
| **QA장** | CAPA 전체 프로세스 총괄, 경영검토 보고 |
| **RA** | 규제 보고 필요성 판정 (FSCA, MDR Vigilance, FDA MDR 등) |

## 6. CAPA 입력원 (Trigger)

| 번호 | 입력원 | 예시 |
|------|--------|------|
| T1 | 고객 불만 | SOP-PMS-001 §불만조사 결과 CAPA 트리거 판정 |
| T2 | 내부감사 지적 | SOP-IA-001 부적합/관찰사항 중 CAPA 요구 건 |
| T3 | 외부감사 지적 | NB/MFDS/FDA 심사 부적합 |
| T4 | 부적합 제품 | 수입검사·공정검사·최종검사 불합격 반복·중대 건 |
| T5 | 경향 분석 | 공정 Cpk 하락, 불만 유형 증가, 반품률 상승 등 |
| T6 | PMS/Vigilance | 부작용 보고, FSCA, 현장 시정조치 |
| T7 | 위험관리 환류 | 생산·생산후 정보로 잔여 위험 재평가 필요 시 |
| T8 | 규제 변경 | 신규 법규·표준으로 기존 적합성 갭 발생 |
| T9 | 변경통제 이행 후 | SOP-CC-001 변경 이행 후 부작용 발견 시 |
| T10 | SW 보안 취약점 | CVD 접수, 침투시험 발견, SBOM 취약점 알림 |

## 7. CAPA 프로세스 흐름

### 7.1 단계 요약

```
[입력원] → (1) 개시·접수 → (2) 분류·우선순위 → (3) 근본 원인 분석
  → (4) 조치 계획 수립 → (5) 승인 → (6) 이행 → (7) 효과 검증 → (8) 종결
```

### 7.2 상세 절차

#### 단계 1: CAPA 개시·접수

1. CAPA 개시자가 **F-CAPA-001 (CAPA 요청서)**를 작성한다.
   - 부적합 사실, 발견 일시·장소, 즉시 시정(Correction) 내용
   - 입력원 유형(T1~T10), 관련 문서·기록 참조
2. QA 담당이 접수하고 CAPA 번호를 부여한다.
   - 번호 체계: `CAPA-YYYY-NNN` (예: CAPA-2026-001)
3. 규제 보고 긴급성을 RA가 1차 판정한다.
   - 긴급(환자 안전) → RA가 SOP-PMS-001에 따라 병행 보고

#### 단계 2: 분류·우선순위

| 등급 | 기준 | 목표 완료 기한 |
|------|------|----------------|
| **Critical** | 환자/사용자 안전 직접 영향, 규제 부적합, FSCA 관련 | 30일 |
| **Major** | 제품 성능 저하, QMS 중대 부적합, 반복 발생 | 60일 |
| **Minor** | 단건 경미 부적합, 문서 오류 | 90일 |

- X-ray 특이사항: 선량 관련(과조사 위험) → 자동 **Critical**
- AI/SW 특이사항: 안전 클래스 C 모듈 관련 → 최소 **Major**

#### 단계 3: 근본 원인 분석 (Root Cause Analysis)

CAPA 조사 책임자가 다음 도구 중 1개 이상을 사용하여 근본 원인을 규명한다.

| 도구 | 적용 상황 |
|------|-----------|
| 5-Why | 단순 인과 관계, 단일 원인 추정 시 |
| Fishbone (Ishikawa) | 복합 원인, 설계·공정·재료·인적 요인 탐색 시 |
| FTA (Fault Tree Analysis) | 안전성 관련 심각 부적합 시 (ISO 14971 연계) |
| Is/Is-Not 분석 | 특정 조건·로트에서만 발생하는 경우 |

- 분석 결과를 **F-CAPA-002 (CAPA 조사·분석 보고서)**에 기록한다.
- 근본 원인이 위험관리 파일(Risk Management File)의 기존 위해와 관련되면, 위험관리 환류(ISO 14971 §10)를 병행한다.

#### 단계 4: 조치 계획 수립

- 시정조치(CA): 근본 원인 제거를 위한 구체적 활동
- 예방조치(PA): 유사 잠재 부적합 방지를 위한 수평전개
- 각 조치에 대해 다음을 명시:
  - 조치 내용, 책임자, 이행 기한
  - 변경통제(SOP-CC-001) 연계 필요 여부
  - 위험관리 파일 갱신 필요 여부
  - 영향받는 문서·양식 목록
- 조치가 기기 안전성·성능에 영향 시 → SOP-CC-001 변경통제 병행

#### 단계 5: 승인

| 등급 | 승인 권한 |
|------|-----------|
| Critical | CAPA Board 합의 + QA장 승인 |
| Major | CAPA Board 합의 |
| Minor | QA 담당 승인 |

- CAPA Board 구성: QA장, 설계 책임자, 생산 책임자, RA (필요 시 보안 담당)
- 승인 기록을 F-CAPA-002에 첨부

#### 단계 6: 이행

- 조치 책임자가 승인된 계획에 따라 이행한다.
- 이행 지연 시 QA 담당에게 사유·재일정을 서면 보고
- 변경통제 대상 건: SOP-CC-001 절차를 병행 수행
- 이행 완료 시 객관적 증거(기록, 사진, 데이터) 확보

#### 단계 7: 효과 검증 (Effectiveness Verification)

- 이행 완료 후 **일정 기간 경과 후**(최소 1회 생산 사이클 또는 30일 중 긴 기간) 효과를 검증한다.
- 검증 방법:
  - 동일 부적합 재발 여부 모니터링
  - 관련 품질 지표(불량률, 불만 건수, Cpk 등) 추이
  - 내부감사 시 해당 항목 특별 확인
- 결과를 **F-CAPA-003 (효과 검증 보고서)**에 기록
- 효과 미흡 시 → 단계 3로 회귀하여 근본 원인 재분석

#### 단계 8: 종결

- QA장(Critical) 또는 QA 담당(Major/Minor)이 효과 검증 결과를 검토하고 종결 판정
- 종결 시 갱신 사항:
  - CAPA 대장(마스터 목록) 상태 갱신
  - 위험관리 파일 갱신 확인
  - 교육 필요 시 SOP-TRN-001 연계
  - 경영검토 입력 자료로 편입

## 8. X-ray / SW 특수 고려사항

### 8.1 방사선 관련 CAPA

- 선량 관련 부적합(과조사, 선량 편차 기준 초과) 발생 시:
  - 즉시 시정: 해당 장비 사용 중지·격리
  - 진단용 방사선 안전관리규칙(제1122호)에 따른 보고 의무 검토
  - ALARA 원칙 재확인, 설계명세(ALARA 지원기능) 검토
- 영상품질 저하 관련 CAPA:
  - 영상품질 QC 프로토콜(05_검사시험) 기준선과 비교
  - IEC 60601-2-54 적합성 재확인

### 8.2 SW/AI 관련 CAPA

- IEC 62304 안전 클래스 C 모듈 관련 CAPA:
  - 소프트웨어 변경 프로세스(IEC 62304 §9) 연계 필수
  - 회귀시험(Regression Test) 범위 확인
- AI 모델 드리프트/편향 관련:
  - SOP-AIGOV-001 거버넌스 프로세스와 연계
  - 재학습 또는 모델 교체 시 SOP-CC-001 변경통제
- 사이버보안 취약점:
  - SOP-CVD-001(조정된 취약점 공개) 연계
  - SBOM 갱신 여부 확인(SOP-SBOM-001)

- 보존 기간: 제품 수명 + 최소 5년 (EU MDR Art.10(8) 요구 시 10년, 이식형은 15년)

## 10. 경영검토 입력

- QA장은 분기별(최소 연 1회) CAPA 현황을 경영검토에 보고한다:
  - 기간 내 개시·종결·미결 건수
  - 등급별·입력원별 분포
  - 효과 검증 미흡 건
  - 반복 발생 부적합 경향
  - 규제 보고 연계 건수
