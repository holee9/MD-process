# IEC 62304 의료기기 소프트웨어 수명주기 프로세스 — v0.2

## 1. 목적

의료기기 SW(X-ray 제어 SW, Detector 펌웨어, 영상처리 SaMD, AI 모듈)에 대해 IEC 62304 기반 수명주기 프로세스의 단계별 수행 절차, 책임, 산출물, 판정 기준을 규정한다.

## 2. 적용 범위

| SW 유형 | 본 프로젝트 적용 예 | IEC 62304 적용 | 안전성 클래스 |
|---------|---------------------|----------------|--------------|
| 제품 내장 SW (SiMD) | X-ray 시스템 제어 SW, Detector 펌웨어, 노출 제어(AEC/APR) | 전체 적용 | Class C |
| 독립 SW (SaMD) | 영상처리·판독 보조 SW | 전체 적용 + IMDRF SaMD | Class B/C |
| AI/ML 모듈 | 이상검출 AI, 선량 최적화 AI | 전체 적용 + GMLP | Class B/C |
| SOUP | OS, 드라이버, OSS, DICOM 스택 | 식별·검증 (§5.1.5, §8) | — |
| 비제품 SW | MES, QMS 문서관리 | 비적용 → ISO/TR 80002-2 | — |

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| SW Item | 소스 코드, 오브젝트 코드, 제어 데이터, 데이터 세트의 식별 가능한 단위 |
| SW Unit | 컴파일·검증이 독립적으로 가능한 최소 코딩 단위 |
| SW System | 통합된 SW 항목들의 집합체 |
| SOUP | Software of Unknown Provenance — 제조사가 개발하지 않았거나 프로세스 불투명한 SW |
| Safety Class | SW 고장 시 위해 심각성에 따른 분류 (A/B/C) |

## 4. 소프트웨어 안전성 클래스 결정 절차

### 4.1 결정 주체 및 시점

| 활동 | 수행자 | 시점 | 입력 |
|------|--------|------|------|
| 초기 클래스 할당 | SW Lead + 위험관리자 | DR0 이전 (DDP 작성 시) | 의도된 사용, 위해 시나리오 |
| 클래스 확정 | SW Lead + QA | DR1 (설계입력 확정 시) | ISO 14971 위험분석 결과 |
| 클래스 재평가 | 위험관리자 | 설계변경 발생 시 | 변경영향분석(SOP-CC-001) |

### 4.2 판정 기준

| 클래스 | 판정 조건 | X-ray 시스템 적용 예 |
|--------|----------|----------------------|
| **A** | SW 고장이 사용자·환자에 상해 가능성 없음 | 로그 뷰어, 유지보수 진단 표시, 버전 정보 화면 |
| **B** | SW 고장이 중대하지 않은 상해 가능, 또는 외부 위험통제로 위해 완화 가능 | 영상 후처리 부가 기능 (밝기/대비 조절), 환자 정보 표시 |
| **C** | SW 고장이 사망·중대 상해 가능 | 노출 제어(kV/mA/타이머), AEC, 인터록 제어, 영상 판독 보조 AI |

Amendment 1:2015 — SW 외부 수단(HW 리미터 등)으로 위험통제가 완전 이전 가능한 경우 클래스 하향 허용. 근거를 위험관리 파일에 문서화 필수.

## 5. 수명주기 단계별 수행 절차

### 5.1 SW 개발 계획 (§5.1)

| 단계 | 수행자 | 활동 | 산출물 | 판정 기준 |
|------|--------|------|--------|-----------|
| 5.1.1 | SW Lead | SW 개발계획서 작성 — 수명주기 모델, 도구, 일정, SOUP 관리전략 포함 | SW 개발계획서 | QA 승인 |
| 5.1.2 | SW Lead | 안전성 클래스별 활동 범위 정의 | 클래스별 활동표 | 위험관리자 검토 |
| 5.1.3 | SW Lead | SOUP 식별 계획 (OSS, DICOM 스택, OS 드라이버) | SOUP 관리계획 | — |
| 5.1.4 | SW Lead | 구성관리·문제해결 절차 연계 | CM Plan 참조 | — |

**X-ray 맥락**: X-ray 제어 SW는 Class C로, 모든 SDLC 활동(상세설계·단위검증 포함) 필수. Detector 펌웨어는 별도 SW 항목으로 식별하고 개발환경(크로스 컴파일러, JTAG) 명시.

### 5.2 SW 요구사항 분석 (§5.2)

| 단계 | 수행자 | 활동 | 산출물 |
|------|--------|------|--------|
| 5.2.1 | SW 엔지니어 | 기능·인터페이스·성능 요구사항 도출 | SRS (SW Requirements Spec) |
| 5.2.2 | 위험관리자 | 위험통제 요구사항 식별 → SRS에 반영 | 위험통제 요구 목록 |
| 5.2.3 | 보안 담당 | 사이버보안 요구사항 반영 (IEC 81001-5-1 §6.1) | 보안 요구 섹션 |
| 5.2.4 | QA | SRS 검토·승인 | 검토 기록 |

**X-ray 맥락 SRS 필수 항목**:
- 노출 시퀀스 제어 (kV/mA/시간 설정 범위, 스텝)
- AEC 응답 특성 (PMMA 두께 범위, 허용 선량 변동)
- DAP 실시간 계산·표시 정확도 (±25%)
- 인터록 조건 (도어, 콜리메이터, Detector 위치)
- DICOM 적합성 (Modality Worklist, Storage, RDSR)

### 5.3 SW 아키텍처 설계 (§5.3) — Class B, C

| 단계 | 수행자 | 활동 | 산출물 |
|------|--------|------|--------|
| 5.3.1 | SW 아키텍트 | SW 항목 분해, 인터페이스 정의 | SAD (SW Architecture Design) |
| 5.3.2 | SW 아키텍트 | SOUP 식별·목록화 (기능, 하드웨어 요구, 알려진 결함) | SOUP 목록 |
| 5.3.3 | 위험관리자 | 아키텍처 수준 위험분석, 장애 격리 검토 | 아키텍처 위험분석 |
| 5.3.4 | 보안 담당 | Threat Modeling (STRIDE), 보안 아키텍처 검토 | 위협 모델 |

**X-ray 시스템 아키텍처 구성 예시**:
- **제어 레이어**: Generator 제어, 인터록 관리 (Class C)
- **Detector 레이어**: FPD 구동 FW, 영상 취득, 교정 (Class C)
- **영상처리 레이어**: 전처리(게인/오프셋 보정), 후처리 (Class B)
- **UI 레이어**: 촬영 워크플로우, 파라미터 표시 (Class B)
- **AI 레이어**: 검출/분류 모델 추론, 결과 오버레이 (Class B/C)
- **통신 레이어**: DICOM, HL7/FHIR, 원격 서비스 (Class A/B)

### 5.4 SW 상세 설계 (§5.4) — Class C만 필수

| 단계 | 수행자 | 활동 | 산출물 |
|------|--------|------|--------|
| 5.4.1 | SW 엔지니어 | SW Unit 수준 상세 설계 | SDD (SW Detailed Design) |
| 5.4.2 | SW 엔지니어 | 인터페이스 상세(데이터 형식, 프로토콜) | 인터페이스 사양 |
| 5.4.3 | 위험관리자 | Unit 수준 위험통제 구현 방안 검토 | — |

**X-ray Class C 상세설계 필수 항목**: AEC 알고리즘(센서 입력→mAs 결정 로직), 노출 시퀀스 상태머신, 인터록 우선순위 로직, 최대 출력 HW 리미트 연동.

### 5.5 SW 단위 구현·검증 (§5.5) — Class B, C

| 단계 | 수행자 | 활동 | 산출물 | 판정 기준 |
|------|--------|------|--------|-----------|
| 5.5.1 | 개발자 | 코딩 표준 준수 구현 | 소스 코드 | 정적분석 Pass |
| 5.5.2 | 개발자/QA | 단위 테스트 수행 | 단위 시험 기록 | 커버리지 ≥80%(Class C) |
| 5.5.3 | 개발자 | 코드 리뷰 (Class C: 필수) | 리뷰 기록 | 크리티컬 결함 0건 |

### 5.6 SW 통합·시험 (§5.6) — Class B, C

| 5.6.3 | SW QA | 회귀 시험 수행 | 회귀 시험 기록 |

**X-ray 통합시험 시나리오**: 제어SW↔Generator HW 명령 응답, Detector FW↔영상처리 SW 영상 전송, AEC 센서→노출 파라미터 자동 조절, DICOM Worklist→촬영→RDSR 전체 워크플로우.

## 7. 위험관리 프로세스 (§7)

| 활동 | 내용 | X-ray 적용 |
|------|------|-----------|

| 위험통제 검증 | 위험통제 조치 유효성 확인 | 고장 주입 시험, 인터록 시험 |

## 10. AMD1:2015 주요 변경 (Edition 1.1)

> **사실관계 정정 (audit #908):** IEC 62304에 **Amendment 2(A2:2020)는 발행된 적이 없다.** 현행 유효 판본은 **IEC 62304:2006/AMD1:2015** (consolidated `IEC 62304:2006+AMD1:2015 CSV`)이며, 2판 작업은 CDV 62304:2021이 2021-05 부결로 종료 후 재가동되어 **Edition 2 발행 예정은 2026-08경**(공식 미발행). 본 문서에서 종전 "A2:2020"으로 인용한 모든 위치는 AMD1:2015로 정정한다.

- **Legacy Software** 조항 신설(AMD1:2015 부속서 신설) → 기존 시판 SW를 본 표준 전체 적용 없이도 위험 평가·gap 분석으로 계속 운영 가능
- 안전 분류 결정 기준 보완 및 SOUP 관리 강화
- (사이버보안 명시적 통합은 IEC 81001-5-1:2021 별도 표준에서 처리 — IEC 62304 본문은 SOUP/위험관리 연계 수준)

**X-ray Legacy 적용**: 기존 출시된 X-ray 제어 SW를 IEC 62304 전면 적용 없이 유지 시, gap 분석 문서(위험평가 + 미준수 항목 + 보완 계획) 필수.

## 11. AI/ML SW 특화 고려

| 항목 | 요구사항 | 참조 |
|------|----------|------|
| 데이터 거버넌스 | 학습·검증·시험 데이터 분리 관리, 데이터셋 기술서 | SOP-AIDATA-001 |
