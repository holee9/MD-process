# PRO-DA-001 데이터 분석 절차

## 1. 목적

본 절차는 QMS의 적합성과 효과성을 실증하고, 개선 가능성을 평가하기 위해 적절한 데이터를 결정·수집·분석하는 방법을 정의한다. ISO 13485 §8.4에서 요구하는 데이터 분석 활동과 통계적 기법의 적용 범위를 포함한다.

## 2. 적용 범위

- QMS 전반의 모니터링·측정 데이터
- 제품 적합성 데이터(검사·시험·불량)
- 프로세스 성과 데이터
- PMS/시판후 피드백 데이터
- 공급자 성과 데이터
- 내부감사·경영검토 결과 데이터

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| KPI | Key Performance Indicator; 핵심 성과 지표 |
| 트렌드 분석 | 시계열 데이터의 경향성을 분석하여 이상 징후를 조기 발견하는 기법 |
| 통계적 기법 | 파레토 분석, 관리도(SPC), 공정능력 분석(Cpk), 회귀분석 등 데이터 기반 의사결정 도구 |
| 예방조치 | 잠재적 부적합의 원인을 제거하여 발생을 방지하는 조치 |

## 4. 책임과 권한

| 역할 | 책임 |
|------|------|
| QA Lead | 데이터 분석 절차 수립·유지, 분석 결과 경영검토 보고, 트렌드 모니터링 |
| 각 프로세스 오너 | 소관 프로세스 데이터 수집·1차 분석, 이상 트렌드 보고 |
| 경영대리인 | 분석 결과에 기반한 개선 의사결정, 자원 배분 |
| RA | 규제기관 보고 데이터(부작용·현장안전시정조치 통계) 분석 |

## 5. 절차

### 5.1 데이터 범주 및 원천

ISO 13485 §8.4에 따라 다음 4개 범주의 데이터를 수집·분석한다:

| 범주 | 데이터 원천 | 주요 지표(KPI 예시) |
|------|------------|---------------------|
| a) 피드백 | 고객 불만, 사용자 설문, PMS 보고, 부작용 보고 | 불만 건수, 반복 불만율, 부작용 보고 건수 |
| b) 제품 적합성 | 수입·공정·최종 검사 기록, 부적합 기록, 반품 데이터 | 불량률(DPPM), 로트 합격률, 반품률 |
| c) 프로세스 특성·추세 | 공정 파라미터, 변경통제 건수, CAPA 건수·완료율, 교육 이수율 | Cpk, CAPA 적시 완료율, 변경 건수 추이 |
| d) 공급자 | 수입 검사 합격률, 공급자 감사 결과, 납기 준수율 | 공급자별 불량률, 납기 적시율 |

### 5.2 데이터 수집

1. 각 프로세스 오너는 소관 KPI 데이터를 월별로 수집한다.
2. 데이터 수집 양식(F-DA-001)을 사용하여 데이터 출처·기간·샘플 크기를 명시한다.
3. 데이터 무결성을 보장하기 위해 원시 데이터(raw data)를 보존한다.
4. 전자 시스템 데이터는 데이터 백업 정책에 따라 관리한다.

### 5.3 통계적 기법 결정

분석 대상에 따라 적절한 통계적 기법을 선택한다:

| 분석 목적 | 권장 기법 |
|-----------|-----------|
| 주요 원인 식별 | 파레토 분석 (80/20 rule) |
| 공정 안정성 모니터링 | 관리도 (X-bar/R chart, p-chart) |
| 공정 능력 평가 | Cpk, Ppk 분석 |
| 추세 파악 | 시계열 분석, 이동평균 |
| 불량 원인 분석 | 특성 요인도 (Fishbone), 5 Why |
| 상관관계 분석 | 산점도, 회귀분석 |

통계적 기법의 적용 범위와 적절성은 연 1회 경영검토 시 재평가한다.

### 5.4 데이터 분석 및 트렌드 모니터링

1. QA Lead는 분기별로 전사 데이터를 종합 분석한다.
2. 트렌드 분석 시 다음 기준으로 이상 신호를 판별한다:
   - 관리 한계 초과 (관리도 기준)
   - 연속 7점 상승/하강 트렌드
   - 전년 동기 대비 유의한 변화
   - 규제 기준값 근접 (예: 방사선 출력 허용 편차의 80% 도달)
3. 이상 트렌드 발견 시 예방조치 기회로 식별하고, 필요 시 CAPA를 개시한다(SOP-CAPA-001).
4. X-ray 장비 특수 데이터:
   - 방사선 출력 안정성 트렌드 (PM 시 측정값)
   - 영상 품질 파라미터 추이 (MTF, DQE, 균일성)
   - Detector 성능 변화 (defect pixel 증가 추이)

### 5.5 분석 결과 보고 및 활용

1. 분기별 데이터 분석 보고서(F-DA-002)를 작성한다.
2. 분석 결과는 다음에 입력으로 활용한다:
   - 경영검토(SOP-MR-001) — §5.6.2 입력 항목 b)
   - CAPA(SOP-CAPA-001) — 예방조치 트리거
   - PMS 보고서(SOP-PMS-001) — 시판후 성과 평가
   - 공급자 재평가(SOP-SUP-001) — 공급자 성과 데이터
3. 경영검토 시 통계적 기법의 적절성과 분석 효과를 평가한다.

### 5.6 기록 유지

1. 데이터 분석 결과 기록은 ISO 13485 §4.2.5에 따라 보관한다.
2. 원시 데이터, 분석 보고서, 트렌드 차트를 포함한다.

## 9. FDA QMSR 실사 대응 — 데이터 분석 (v0.3 추가)

### 9.1 CP 7382.850 데이터 분석 중점 확인 사항

FDA QMSR 하에서 ISO 13485 §8.4가 직접 적용된다. CP 7382.850 실사 시 데이터 분석 영역의 중점 확인 항목:

| 실사 확인 항목 | ISO 13485 근거 | 대응 증적 |
|--------------|---------------|----------|
| 피드백 데이터 수집·분석 절차 존재 | §8.2.2 + §8.4 a) | PRO-DA-001 §5.1 범주 a) + F-DA-001 |
| 제품 적합성 데이터 분석 (불량률 등) | §8.4 b) | F-DA-001 분기 보고서 — 제품 적합성 섹션 |
| 프로세스 특성·추세 분석 | §8.4 c) | F-DA-001 관리도·Cpk 분석 결과 |
| 공급자 데이터 분석 | §8.4 d) | F-DA-001 공급자 성과 섹션 |
| 통계적 기법 적절성 문서화 | §8.1 | F-DA-002 통계적 기법 적용 기록 |
| 분석 결과 → 개선 조치 연계 | §8.5 | CAPA·경영검토 입력 추적 |
| 데이터 분석 결과 경영검토 입력 | §5.6.2 | SOP-MR-001 경영검토 회의록 |

### 9.2 QMSR 하 Warning Letter 빈발 지적 패턴 (데이터 분석 관련)

| 지적 유형 | 예방 대책 |
|----------|----------|
| 데이터 수집은 하나 분석을 수행하지 않음 | 분기별 F-DA-001 보고서 작성 의무화 (§5.5) |
| 트렌드 분석 미수행 (단순 건수 집계만) | §5.3 통계적 기법 필수 적용 — 관리도·파레토 최소 1개 |
| 분석 결과에 대한 조치 미기록 | F-DA-001에 "조치 권고" 란 필수 기재 + CAPA 연계 여부 |
| 통계적 기법 선택 근거 미문서화 | F-DA-002에 "기법 선택 근거" 란 기재 |

## 10. EUDAMED 데이터 연계 분석 (v0.3 추가)

### 10.1 EUDAMED 발생 데이터의 QMS 데이터 분석 편입

EUDAMED 의무화(2026-05-28)에 따라 EUDAMED에서 발생하는 데이터를 QMS 데이터 분석 범주에 편입한다:

| EUDAMED 모듈 | 추출 데이터 | 분석 범주 | 분석 주기 |
|-------------|-----------|----------|----------|
| Market Surveillance | 해당 제품군 안전성 이슈·리콜 정보 | a) 피드백 | 월간 |
| UDI/Device | 자사 등록 기기 정보 정확성·최신성 | c) 프로세스 | 분기 |
| Certificates | NB 인증서 상태·유효기간 | c) 프로세스 | 분기 |
| Vigilance (가동 시) | 자사 Vigilance 보고 건수·유형·응답 시간 | a) 피드백 | 월간 |

### 10.2 경쟁 제품 안전성 벤치마킹

EUDAMED Market Surveillance 모듈에서 동일 EMDN 코드 제품군의 FSCA·리콜 데이터를 수집하여 자사 제품 대비 안전성 벤치마킹을 수행한다. 결과는 경영검토 입력 사항으로 보고한다.

## 11. AI/ML 성능 드리프트 모니터링 (v0.3 추가)

### 11.1 적용 대상

자사 X-ray 시스템에 AI/ML 구성요소가 포함된 경우(SOP-AIGOV-001 적용 대상), 다음 AI 성능 데이터를 데이터 분석 범주에 추가한다:

| 모니터링 항목 | 측정 지표 | 이상 판정 기준 | 조치 |
|-------------|----------|--------------|------|
| 모델 성능 드리프트 | AUC, Sensitivity, Specificity 추이 | 사전 정의 성능 임계값 대비 5% 이상 저하 | CAPA 검토 + SOP-AIGOV-001 재검증 |
| 데이터 분포 드리프트 | KL Divergence, PSI | PSI > 0.2 (유의한 변화) | 데이터셋 재평가 (SOP-AIDATA-001) |
| 편향(Bias) 모니터링 | 하위그룹별 성능 격차 | 그룹 간 AUC 차이 > 0.05 | SOP-AIGOV-001 공정성 검토 |

### 11.2 IEC 62304 Ed2 대비

IEC 62304 Ed2(2026년 8월 발행 예정)에서 AI/ML 수명주기 프레임워크가 신규 도입된다. 발행 확정 시:

- AI 성능 모니터링 데이터를 ISO 13485 §8.4 데이터 분석과 IEC 62304 Ed2 AI 수명주기 모니터링 요구사항에 이중 매핑
- 통계적 기법에 AI 드리프트 탐지 기법(CUSUM, ADWIN 등) 추가 (F-DA-002 기법 목록 갱신)

### 11.3 MFDS AI 구성요소 사전 성능평가 대응

MFDS가 2026년 6월부터 AI 구성요소 사전 성능평가를 적용할 예정이다. 데이터 분석 절차에서:

- AI 구성요소별 성능평가 데이터를 별도 범주로 수집
- 사전 성능평가 결과와 시판 후 실성능 간 괴리 분석
- 괴리 발견 시 CAPA 및 재허가 검토 트리거
