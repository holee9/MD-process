# 문서 메타데이터 (Frontmatter) 규칙

> 본 프로젝트의 모든 .md 문서(단, 로그·draft·README·템플릿 제외)는 상단에 YAML frontmatter를 포함합니다.
> 매트릭스·대시보드·자동 검증이 이 메타데이터를 단일 진실원(SSOT)으로 사용합니다.

## 1. 적용 범위

| 적용 | 미적용 |
|------|--------|
| SOP·절차서·지침서·매뉴얼 | `README.md` |
| 양식·체크리스트 | `_TEMPLATE.md`, `_log.json` |
| 매트릭스·매핑표·요약표 | `issue-drafts/*.md` (별도 frontmatter) |
| 가이드·계획서·보고서 | 일일 리서치 로그(`11_*/`)는 경량 frontmatter (type: Log) |

## 2. 필드 정의

```yaml
---
doc-id: SOP-CC-001
title: 변경통제 절차
type: SOP
version: v0.1
status: draft
category: 02_품질경영시스템_QMS
purpose: 설계·SW·생산 변경의 영향 평가·승인 통제
applicable:
  - ISO13485:2016 §7.3.9
  - FDA QMSR 820.30
  - EU MDR Annex IX §2.4
forms: [F-CC-001, F-CC-002, F-CC-003, F-CC-004, F-CC-005]
related-docs: [SOP-SBOM-001, SOP-AIGOV-001]
related-issues: [12, 39, 42]
owner: RA/QA Lead
last-review: 2026-04-30
review-due: 2027-04-30
---
```

### 2.1 필수 필드

| 필드 | 설명 | 예시 |
|------|------|------|
| `doc-id` | 문서 고유 ID. 패턴: `<TYPE>-<DOMAIN>-<NNN>`. 양식·체크리스트는 별도 prefix(F-, CHK-) | `SOP-CC-001`, `F-CC-001`, `CHK-IEC60601-2-54` |
| `title` | 문서 제목. 큰따옴표로 묶어도 됨 | `변경통제 절차` |
| `type` | 문서 유형 (아래 enum) | `SOP` |
| `version` | 현재 버전. semver 또는 v0.X | `v0.2` |
| `status` | 라이프사이클 상태 (아래 enum) | `draft` |
| `category` | 카테고리 폴더명 | `02_품질경영시스템_QMS` |
| `purpose` | 문서 용도 한 줄 요약 (40~80자) | `설계·SW·생산 변경의 영향 평가·승인 통제` |

### 2.2 권장 필드

| 필드 | 설명 |
|------|------|
| `applicable` | 적용 표준·법규 목록. 가능하면 조항까지 명시 |
| `forms` | 본 문서가 사용하는 양식 doc-id 목록 |
| `related-docs` | 강한 의존이 있는 다른 문서의 doc-id |
| `related-issues` | 연관 GitHub Issue 번호 (정수) |
| `owner` | 문서 소유 책임자 (역할명 또는 이름) |
| `last-review` | 최종 검토일 (YYYY-MM-DD) |
| `review-due` | 다음 검토 만료일 (YYYY-MM-DD). 비우면 `last-review + 1 year` 적용 |

## 3. Enum 정의

### 3.1 `type`

| 값 | 설명 |
|----|------|
| `SOP` | Standard Operating Procedure |
| `Procedure` | 일반 절차서 (SOP보다 비공식) |
| `Form` | 기록 양식 (F-NNN-NNN) |
| `Checklist` | 체크리스트 (CHK-) |
| `Matrix` | 매트릭스·매핑표 |
| `Plan` | 계획서 (사용적합성 계획서, Pen-test 계획서 등) |
| `Report` | 보고서 (교차검증·갭 분석 등) |
| `Guide` | 가이드·매뉴얼 |
| `Spec` | 명세서 (설계 명세 등) |
| `JD` | 직무기술서 |
| `Index` | 색인 (`색인_INDEX.md` 등) |
| `Overview` | 카테고리 개요 (`*_개요.md`) |
| `Log` | 일일 리서치 로그 등 (경량 frontmatter) |

### 3.2 `status`

| 값 | 설명 |
|----|------|
| `draft` | 초안 작성 중 |
| `review` | 내부 검토 중 |
| `approved` | 책임자 승인 완료 |
| `released` | 정식 배포·운영 적용 |
| `obsolete` | 폐기·대체됨 |

## 4. 작성 규칙

1. **frontmatter는 파일 최상단에 위치** (BOM·공백 라인 금지)
2. YAML 문법 준수: 들여쓰기 2칸, 콜론 뒤 공백 1칸
3. 문자열에 콜론·따옴표 포함 시 큰따옴표로 감싸기
4. 신규 문서 작성 시 모든 필수 필드 채우기. 권장 필드는 알 수 없을 때 비워두거나 `[]`
5. 버전 올릴 때 `version` + `last-review` 갱신, 필요 시 `review-due` 자동 재계산
6. `status` 전이는 `draft → review → approved → released → obsolete` 단방향 (특수 케이스만 역행)

## 5. 검증

- GitHub Actions `validate-frontmatter.yml`이 push마다 frontmatter 스키마 검증
- doc-id 중복, 필수 필드 누락, enum 위반, related-issues가 실제 이슈와 매칭되는지 등

## 6. 자동 활용

- `00_프로젝트관리/문서_매트릭스.md` 자동 생성 (push 시)
- README 대시보드의 카테고리×유형 카운트 자동 갱신
- review-due 만료 임박 문서 자동 알림 (계획)
- 감사 대응: `applicable` 기반 표준 충족 문서 즉시 조회 가능

## 7. 예외

- `11_일일_리서치로그/*.md`, `12_교차검증_보고서/*.md` 는 경량 frontmatter:
  ```yaml
  ---
  doc-id: LOG-2026-05-06
  title: 일일 리서치 로그 2026-05-06
  type: Log
  category: 11_일일_리서치로그
  purpose: 일일 리서치 결과 기록
  ---
  ```
- `issue-drafts/*.md` 는 자체 frontmatter(title/labels/state) 사용. 본 규칙 미적용
