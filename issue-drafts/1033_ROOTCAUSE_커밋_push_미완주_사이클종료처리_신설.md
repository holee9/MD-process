결과적으로 **로컬의 보강 성과**(FDA RTA 0→83%, owner TBD 근본원인 차단, 생존 감시, SOP-PRES-001)와 **origin의 감사 성과**(#1032~#1060)가 서로에게 전혀 반영되지 않은 채 양쪽이 독립 진행했다. origin 기준 FDA RTA는 여전히 0%, owner TBD 30건 잔존 상태였다.

## 근본원인

1. **락 잔존으로 인한 연쇄 차단**: 일부 실행 환경에서 파일 삭제가 막혀 `.git/*.lock`이 남으면, 이후 **모든** git 명령이 실패한다. 사이클은 작업까지 마치고 커밋 단계에서 조용히 죽는다.
2. **커밋·push가 보장된 단계가 아니었음**: 사이클 정의상 마무리가 선택적이어서, 실패해도 아무도 모르고 다음 사이클이 같은 상태로 또 시작된다.
3. **감시의 사각지대**: #1031에서 만든 생존 감시는 *커밋일*만 봤다. "작업은 하는데 커밋만 안 되는" 유형은 커밋일이 갱신되지 않아 임계 도달 전까지 정상으로 보인다.

## 조치 (2026-09-18)

1. **`scripts/sync_and_push.sh` 신설** — 사이클 종료 처리. 락 정리(rm 실패 시 rename 우회) → 커밋 → fetch/merge → 자동생성물 재빌드 → push → **사후검증**(origin과 일치 확인). 멱등.
2. **`check_pipeline_health.py` 보강** — 워킹트리 미커밋(임계 0건)·미push 커밋을 감시 항목에 추가. 클론 환경용 `--skip-local` 옵션 제공.
3. **`pipeline-health.yml`** — GitHub Actions는 신규 클론이므로 `--skip-local` 적용(오탐 방지).
4. **README §자동화 시스템** — 사이클 종료 처리 호출을 **필수 단계로 명문화**.
5. **분기 해소** — origin 50커밋과 로컬 8커밋을 병합(충돌 8건: 자동생성물 4건은 재빌드로, frontmatter 4건은 origin 본류 값 채택) 후 push. 양쪽 성과 통합 완료.
