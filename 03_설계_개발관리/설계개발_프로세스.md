# 설계·개발 관리 프로세스 — v0.2

> v0.2 — 2026-05-09: DHF 구조 상세화, V&V 절차 구체화, 설계이전 기준 추가, X-ray/SW/AI 특수 고려사항 보강, 규제 매핑 강화

## 1. 목적

본 문서는 의료용 X-ray 시스템(HW·detector·SW·AI 구성요소 포함)의 설계·개발 전 과정에 대한 관리 프로세스를 정의한다. ISO 13485:2016 §7.3, FDA QMSR(21 CFR 820 → ISO 13485 참조편입), EU MDR Annex II 기술문서 요구, MFDS GMP 별표2 설계관리 요구를 충족한다.

## 2. 적용 범위

- X-ray 시스템 하드웨어 (tube, generator, mechanical)
- Flat panel detector (digital radiography)
- 의료기기 소프트웨어 (IEC 62304 Class B/C)
- AI/ML 구성요소 (CAD, 자동 노출 보정 등)
- 사용자 인터페이스 (IEC 62366-1)
- 부속품 및 인터페이스 장비

## 3. 근거 표준·법규

| 표준/법규 | 관련 절 | 요구사항 |
|-----------|---------|----------|
| ISO 13485:2016 | §7.3.1~7.3.10 | 설계개발 기획~변경 관리 전 과정 |
| FDA QMSR | 21 CFR 820 → ISO 13485 편입 | Design Controls (구 820.30 대응) |
| EU MDR 2017/745 | Annex II §1~6 | 기술문서 구조 (설계 산출물 포함) |
| IEC 62304:2006+A1 | 전체 | SW 수명주기 프로세스 |
| IEC 62366-1:2015+A1 | 전체 | 사용적합성 엔지니어링 |
| IEC 60601-2-54 | §201~203 | X-ray 특수 안전·성능 요구 |
| ISO 14971:2019 | 전체 | 위험관리 (설계 전 단계 연계) |
| MFDS GMP 별표2 | §7.3 | 설계개발 관리 |

## 4. 설계·개발 단계 및 요구사항

### 4.1 설계·개발 기획 (ISO 13485 §7.3.2)

**입력:** 제품 컨셉, 시장 요구, 규제 요구, 선행 위험분석
**산출물:** 설계개발 계획서 (Design and Development Plan, DDP)

DDP 필수 포함 사항:
- 설계·개발 단계 정의 및 단계 게이트(Phase Gate) 기준
- 각 단계별 검토·검증·밸리데이션 활동
- 책임 및 권한 배정
- 인터페이스 관리 (HW↔SW↔detector↔AI 팀 간)
- 일정 및 자원
- 위험관리 활동 연계 (ISO 14971 §4.1 위험관리 계획)
- 설계개발 파일(DHF) 구조

### 4.2 설계 입력 (ISO 13485 §7.3.3)

**산출물:** 설계입력서(Design Input Specification, DIS)

| 입력 범주 | 예시 (X-ray 시스템) |
|-----------|---------------------|
| 사용자 요구 | 촬영 워크플로우, 디스플레이 요구, 사용 환경 |
| 규제 요구 | IEC 60601-2-54 안전·성능, MFDS 허가 조건, FDA 510(k)/De Novo |
| 성능 요구 | kVp 범위, mAs 정밀도, 영상 해상도(DQE, MTF), 선량 |
| 안전 요구 | 방사선 방호(ALARA), 전기안전, 기계적 안전 |
| 인터페이스 요구 | DICOM 적합성, HL7/FHIR 연동, 병원 RIS/PACS 연계 |
| 위험통제 요구 | ISO 14971 위험분석 결과에서 도출된 설계 요구 |
| SW 요구 | IEC 62304 SW 요구사항 명세, 사이버보안 요구(IEC 81001-5-1) |
| AI 요구 | 학습 데이터셋 기준, 성능 메트릭(AUC, 민감도, 특이도), 공정성 |
| 사용적합성 요구 | IEC 62366-1 사용 시나리오, 사용 오류 분석 |
| 라벨링 요구 | EU MDR Annex I §23, MFDS 표시기재, UDI |

설계 입력은 **완전성·모호성 제거·상호 모순 없음·검증 가능성**을 검토 후 승인.

### 4.3 설계 출력 (ISO 13485 §7.3.4)

**산출물:** 도면, SW 아키텍처·상세설계서, 사양서, BOM, 라벨링, 제조 절차서

설계 출력 요구:
- 설계 입력 대비 추적 가능 (요구사항 추적 매트릭스, RTM)
- 검증·밸리데이션 합격 기준 포함
- 안전 관련 특성 식별 (Critical-to-Quality, CTQ)
- SW 출력: 소스코드, 빌드 아티팩트, SBOM (SOP-SBOM-001)
- 제조·서비스에 필수 정보 포함

### 4.4 설계 검토 (ISO 13485 §7.3.5)

각 단계 게이트에서 설계검토(Design Review) 실시:

| 게이트 | 주요 검토 사항 | 참석 필수 |
|--------|---------------|-----------|
| DR0 — 기획 완료 | DDP 적절성, 자원·일정 실현성 | PL, QA, RA |
| DR1 — 입력 확정 | DIS 완전성, 위험분석 초기 결과 | PL, 설계, QA, RA, 사용적합성 |
| DR2 — 상세설계 완료 | 아키텍처, 상세설계, FMEA | 설계, SW, QA, 제조 |
| DR3 — 검증 완료 | V&V 결과, 잔여 위험 평가 | PL, 설계, QA, RA |
| DR4 — 밸리데이션 완료 | 임상평가, 사용적합성 평가 결과, 최종 위험평가 | 전체 (경영진 포함) |
| DR5 — 이전 완료 | 양산 준비도, 제조 절차 확정 | PL, 제조, QA |

검토 결과 기록: 참석자, 검토 항목, 결정사항, 후속 조치(Action Item), 책임자·기한

### 4.5 설계 검증 (ISO 13485 §7.3.6)

설계 출력이 설계 입력을 충족하는지 객관적 증거로 확인.

**검증 활동 예시 (X-ray 시스템):**

| 검증 항목 | 방법 | 합격 기준 | 근거 |
|-----------|------|-----------|------|
| kVp 정확도 | 계측기 측정 (3회 반복) | ±5% 이내 | IEC 60601-2-54 §203.6.4 |
| mAs 재현성 | 반복 조사 (10회) | CV ≤ 5% | IEC 60601-2-54 §203.6.5 |
| 반가층(HVL) | Al 필터 측정 | 규격 범위 내 | IEC 60601-2-54 §203.6.3 |
| detector DQE | IEC 62220-1-1 프로토콜 | ≥ spec | IEC 62220-1-1 |
| 전기안전 | 접지 저항, 누설 전류 | IEC 60601-1 §8 | IEC 60601-1 |
| EMC | 방출·내성 시험 | IEC 60601-1-2 | IEC 60601-1-2 |
| SW 단위·통합 테스트 | 자동화 테스트 + 수동 | 100% pass, 코드 커버리지 ≥ 80% (Class C) | IEC 62304 §5.5~5.6 |
| 사이버보안 | SAST, DAST, 침투시험 | 고위험 취약점 0건 | IEC 81001-5-1, FDA Cybersecurity |
| SBOM 무결성 | SBOM 생성·VEX 검증 | 알려진 고위험 CVE 0건 | SOP-SBOM-001 |
| AI 성능 | 독립 테스트셋 평가 | AUC ≥ spec, 편향 ≤ 허용치 | SOP-AIGOV-001 |

검증 프로토콜 → 검증 보고서 → 편차 시 재설계 또는 위험평가 → DHF 기록

### 4.6 설계 밸리데이션 (ISO 13485 §7.3.7)

최종 제품이 의도된 사용 조건에서 사용자 요구를 충족하는지 확인.

**밸리데이션 활동:**

| 활동 | 내용 | 근거 |
|------|------|------|
| 임상평가 | 문헌 기반 또는 임상시험 (EU MDR Art.61) | EU MDR, MFDS |
| 사용적합성 평가 | Summative Usability Test (IEC 62366-1 §5.9) | IEC 62366-1 |
| SW 시스템 밸리데이션 | 실사용 환경 시나리오 테스트 | IEC 62304 §5.7 |
| 영상품질 임상적 적합성 | 팬텀·임상 영상 평가 | IEC 60601-2-54, 전문의 판독 |
| AI 임상 밸리데이션 | 실제 임상 데이터 독립 평가 | SOP-AIGOV-001, FDA AI/ML guidance |
| 환경 밸리데이션 | 운송·보관·사용 환경 조건 시험 | IEC 60601-1 §5 |
| 설치 밸리데이션 (IQ) | 설치 후 성능 확인 | QC-IQ-001 |

**밸리데이션 조건:**
- 초기 양산 또는 동등품으로 실시 (시작품이 아닌 양산 공정 산출물 사용)
- 의도된 사용 환경 대표 조건
- 규제 제출용 밸리데이션은 독립 수행
- 결과 DHF에 기록

### 4.7 설계 이전 (ISO 13485 §7.3.8)

설계 산출물을 제조로 이전하는 절차.

**이전 완료 기준 (Transfer Checklist):**

| 항목 | 확인 내용 | 승인 |
|------|-----------|------|
| 제조 사양서 확정 | 도면·BOM·SW 릴리스 패키지 최종 버전 동결 | 설계 + 제조 |
| 제조 절차서 확정 | SOP-MFG-001, 작업지시서, 검사기준서 | 제조 + QA |
| 특수공정 밸리데이션 | 해당 공정 IQ/OQ/PQ 완료 | QA |
| 수입검사 기준 | 원자재·부품 수입검사 규격 확정 | QA + 구매 |
| 출하검사 기준 | 최종 출하시험 항목·합격 기준 확정 | QA |
| 금형·치공구 | 양산용 금형·치공구 검증 완료 | 제조 |
| 라벨링·포장 | UDI 확정, 포장 사양 확정 | RA + QA |
| 교육 | 제조·검사 인원 교육 완료 | 교육 담당 |
| 위험관리 보고서 | ISO 14971 잔여 위험 수용 최종 승인 | 위험관리 팀 |
| DHF 완결성 검토 | DHF 전체 문서 완결 확인 | QA |
| 규제 승인 | MFDS 허가/FDA 510(k) clearance 확보 (해당 시) | RA |

이전 완료 후 제조 개시 승인 (경영진 또는 지정 권한자)

### 4.8 설계 변경 (ISO 13485 §7.3.9)

- 설계 변경은 **SOP-CC-001 변경통제 절차**를 통해 관리
- 변경 영향 평가: 안전·성능·규제 적합성 재확인
- 선량 변경, SW 주요 변경 시 재검증·재밸리데이션 범위 결정
- EU MDR: Significant Change 판단 기준 적용
- FDA: Letter-to-File vs. 510(k) 재제출 판단
- 변경 이력 DHF에 기록

## 5. 설계이력파일(DHF) 구조

ISO 13485 §7.3.10에 따라 각 의료기기(군)별 DHF를 유지한다.

### 5.1 DHF 표준 목차

```
DHF-[제품코드]/
├── 01_설계개발_계획서 (DDP)
├── 02_설계입력서 (DIS)
│   ├── 사용자_요구사항
│   ├── 규제_요구사항
│   ├── 성능_안전_요구사항
│   └── 요구사항_추적_매트릭스 (RTM)
├── 03_설계출력
│   ├── 시스템_아키텍처
│   ├── HW_도면_BOM
│   ├── SW_설계문서 (SRS, SDS, SAD)
│   ├── 라벨링
│   └── 제조_사양서
├── 04_위험관리파일 (RMF)
│   ├── 위험관리_계획서
│   ├── 위험분석 (FTA, FMEA, FMECA)
│   ├── 위험통제_기록
│   └── 위험관리_보고서
├── 05_설계검토_기록
│   └── DR0~DR5_회의록
├── 06_설계검증
│   ├── 검증_프로토콜
│   ├── 검증_보고서
│   └── 편차_기록
├── 07_설계밸리데이션
│   ├── 임상평가_보고서
│   ├── 사용적합성_평가
│   ├── SW_밸리데이션
│   └── AI_밸리데이션 (해당 시)
├── 08_설계이전_기록
│   ├── 이전_체크리스트
│   └── 양산_승인_기록
├── 09_설계변경_이력
│   └── (SOP-CC-001 연계)
└── 10_기술문서 (EU MDR Annex II 대응)
    ├── 장치_설명_사양
    ├── 적용_표준_정합_목록
    ├── 안전_성능_필수요구사항(GSPR) 체크리스트
    └── 라벨링_사용설명서
```

### 5.2 DHF 관리 원칙

- DHF는 전자문서관리시스템(EDMS) 또는 버전관리 리포지토리에서 유지
- 문서 변경 시 SOP-CC-001 적용, 버전 이력 추적
- DHF 완결성 검토: 설계이전(DR5) 전 QA 검토 필수
- 접근 권한: 설계팀 쓰기, 전사 읽기, QA 승인 권한
- 보존 기간: 제품 수명 + 5년 (EU MDR 대상: 10년/15년)

## 6. 위험관리 연계

- 설계 전 단계에서 ISO 14971:2019 위험관리 프로세스 병행
- 설계 입력에 위험통제 요구사항 반영 → 출력에서 구현 → 검증에서 확인
- 위험관리 파일(RMF)은 DHF §04에 포함
- 잔여 위험 수용은 설계이전(DR4/DR5) 전 경영진 승인
- 생산 후 정보(PMS) → 위험관리 갱신 → 설계 변경 트리거 가능

## 7. SW 개발 특수 사항 (IEC 62304 연계)

- SW 안전 분류(Class A/B/C) → 설계 입력 단계에서 결정
- SW 요구사항 → SW 아키텍처 → 상세설계 → 구현 → 검증(단위·통합·시스템)
- SW 구성관리: 소스코드 버전관리, 빌드 재현성
- SOUP/OTS 관리: 위험평가, 이상보고 모니터링
- SW 문제해결 프로세스 (IEC 62304 §9) → SOP-NC-001 연계
- 사이버보안: IEC 81001-5-1, Threat Modeling, SBOM (SOP-SBOM-001)

## 8. AI/ML 구성요소 특수 사항

- AI 성능 요구사항을 설계 입력에 명시 (SOP-AIGOV-001)
- 학습 데이터셋 관리 (SOP-AIDATA-001)
- AI 모델 검증: 독립 테스트셋, 교차검증, 편향 분석
- AI 밸리데이션: 실제 임상 데이터, 다기관 평가
- 드리프트 모니터링 계획 → PMS 연계
- FDA AI/ML SaMD 가이던스: PCCP(Predetermined Change Control Plan) 해당 시 설계 입력에 포함

## 9. 실무 체크포인트

- 설계 입력에 규제·사용자·성능·안전·사이버보안 요구를 모두 포함했는가
- 각 단계 게이트 전 독립 검토자(QA/RA) 승인을 받았는가
- 요구사항 추적 매트릭스(RTM)가 입력↔출력↔검증↔밸리데이션 전 구간 추적 가능한가
- 위험관리 활동이 설계 전 단계와 동기화되어 있는가
- 변경 시 영향 범위 평가와 재검증 범위가 결정되었는가
- DHF가 EU MDR Annex II 기술문서 구조에 대응 가능한가
- 설계이전 체크리스트가 모두 완료되었는가
