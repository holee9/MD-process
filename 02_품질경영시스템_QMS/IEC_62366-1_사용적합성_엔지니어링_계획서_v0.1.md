# IEC 62366-1 사용적합성 엔지니어링 계획서

문서번호: PLAN-USE-001
버전: v0.2
작성일: 2026-04-26 (초안) / 2026-05-22 (보강)
작성자: 의료기기 업무규칙 개발팀

## 1. 목적
의료용 X-ray 시스템/검출기/소프트웨어의 사용 환경에서 발생할 수 있는 사용오류(Use Error)를 체계적으로 식별·통제하기 위해 IEC 62366-1:2015+Amd1:2020의 사용적합성 엔지니어링(UE) 프로세스를 설계·개발 수명주기에 통합 적용한다.

## 2. 규제·표준 근거
- IEC 62366-1:2015+Amd1:2020 — Application of usability engineering to medical devices
- IEC/TR 62366-2:2016 — Guidance on the application of usability engineering
- FDA "Applying Human Factors and Usability Engineering to Medical Devices" (2016)
- FDA "List of Highest Priority Devices for Human Factors Review" (2016 Draft; 2022-12 "Content of Human Factors Information in Medical Device Marketing Submissions" Draft로 대체)
- MDCG 2019-16 Rev.1 — Cybersecurity (UI 보안 인터랙션 부분)
- MFDS "의료기기 사용적합성 평가 가이드라인" (2020)
- ISO 14971:2019 §4.1.2 (Use error → Hazard 연계)
- AAMI HE75:2009/(R)2018 — Human Factors Design
- EU AI Act Art.13(투명성), Art.14(인간감독)
- 디지털의료제품법 — 사용적합성 자료 제출 요구 (국내법 근거조문 미확인(§) — audit #957 D3, 종전 "법 제15조" 오귀속 삭제; 제15조="실사용 평가"로 사용적합성과 무관)

## 3. 적용 범위

| 구성요소 | UE 적용 수준 | X-ray 특화 고려사항 |
|----------|-------------|-------------------|

| 환자 위치결정 보조 디스플레이 | ● Full | 해부학적 위치 가이드, SID 표시 |

## 4. UE 프로세스 단계별 절차 (IEC 62366-1 §5)

### 4.1 프로세스 흐름

```
§5.1 사용 사양 작성 (Use Specification)
  ├── 의도된 사용 정의 (X-ray 촬영, AI 진단보조)
  ├── 환자 집단 (소아~성인, 이동식/고정식)
  ├── 사용 환경 (영상의학과, 응급실, 수술실, 이동식)
  └── 사용자 프로파일 (방사선사, 영상의학 전문의, 정형외과의)
       ↓
§5.2 UI 평가 우선순위 결정
  └── 위험 기반 우선순위: Critical Task 식별 (§6 참조)
       ↓
§5.3 알려진/예측 가능 사용오류 식별
  ├── 문헌 조사 (MAUDE DB, 유사기기 리콜, 학술논문)
  ├── 사용자 관찰·인터뷰 (방사선사 5~8명)
  ├── 기존 제품 필드 데이터 분석 (불만/사고 기록)
  └── X-ray 특화: 오인 환자 촬영, 과피폭, AEC 오동작
       ↓
§5.4 위험 분석 (HRUS — Hazard-Related Use Scenarios)
  ├── 각 Use Error → Hazardous Situation → Harm 매핑
  ├── ISO 14971 RMF에 통합 (SOP-RM-001 연계)
  └── X-ray: 방사선 피폭 Harm → Severity 평가
       ↓
§5.5 UI 사양 작성 (UI Specification)
  ├── 화면 레이아웃·네비게이션 구조
  ├── 경고/확인 다이얼로그 설계
  ├── 색상/아이콘/폰트 가독성 기준
  └── X-ray: 방사선 발사 전 확인 UI, 선량 표시, 콜리메이션 가이드
       ↓
§5.6 UI 평가 계획 (Formative + Summative)
  └── §5 참조
       ↓
§5.7 Formative Evaluation (반복)
  └── §5 참조
       ↓
§5.8 Summative Evaluation
  └── §5 참조
       ↓
§5.9 UEF 컴파일
  └── §11 산출물 참조
```

## 5. Formative vs Summative 평가

| 항목 | Formative | Summative |
|------|-----------|-----------|
| 시점 | 설계 초기/중기 (반복 2~3회) | 설계 동결 후 1회 (주요변경 시 재실시) |
| 참가자 | 5~8명/사용자 그룹 (Nielsen 권장) | 사용자 그룹별 ≥15명, 다중 그룹 시 합계 ≥45명 (FDA 권장) |
| 환경 | 실험실·HiFi 프로토타입 | 실사용 환경 (모사 포함) |
| 측정 | 발견적 문제·태스크 흐름 | 위험 기반 Critical Task 통과율 |
| 데이터 | 정성+정량 | 정량(통과/실패) + 근본원인 |
| 합격기준 | 반복 개선 목표 달성 | 사전 정의 P/F + Use Error → 위험통제 충분성 평가 |

### 5.1 X-ray 시스템 Formative 평가 시나리오 예시

| 시나리오 | 평가 목적 | 사용자 그룹 |
|----------|----------|------------|
| 응급 흉부 촬영 (시간 압박) | 프로토콜 선택 속도, 환자 매칭 오류율 | 방사선사 |
| 소아 복부 촬영 | 소아 프로토콜 접근성, 선량 설정 적절성 | 방사선사 |
| AI 진단 결과 검토 | 결과 해석 정확도, Automation Bias | 영상의학 전문의 |
| Foot Switch 오발사 방지 | 의도하지 않은 방사선 발사 빈도 | 방사선사 |
| 서비스 모드 교정 | 교정 파라미터 오입력 방지 | 서비스 엔지니어 |

## 6. Critical Task 정의 및 분석

### 6.1 정의
실패 시 환자/사용자에게 심각한 위해가 발생하거나 진단 정확성에 영향을 미치는 태스크.

### 6.2 식별 절차
Use Specification → Task Analysis → HRUS → Critical Task 식별 → Summative 합격기준 설정

### 6.3 X-ray 시스템 Critical Task 목록

| CT# | Critical Task | 관련 위해 | Severity | 합격기준 (Summative) |
|-----|--------------|----------|----------|---------------------|
| CT-01 | 환자정보 매칭 | 오인 환자 촬영 → 불필요 피폭 | Critical | 통과율 100% (0 Use Error) |
| CT-02 | 검사 프로토콜 선택 | 부적절 선량/부위 → 재촬영/과피폭 | Serious | 통과율 ≥95%, 잔여 오류 위험 수용 |
| CT-03 | kVp/mAs/AEC 설정·Override | 과피폭/저피폭 → 진단 불량 | Critical | 통과율 100% |
| CT-04 | 콜리메이션 및 SID 설정 | 조사야 과다 → 불필요 피폭 | Serious | 통과율 ≥95% |
| CT-05 | 방사선 노출 발사 (Foot Switch) | 오발사 → 불필요 피폭 | Critical | 통과율 100% |
| CT-06 | 후속 노출 차단 (Interlock 해제) | 연속 오발사 → 과피폭 | Critical | 통과율 100% |
| CT-07 | AI 진단보조 결과 수용/거부 | 위양성/위음성 수용 → 오진 | Serious | Automation Bias 시나리오 포함, 통과율 ≥90% |
| CT-08 | 응급정지 (Emergency Stop) | 즉각 정지 불가 → 과피폭/물리적 위해 | Critical | 반응시간 ≤3초, 통과율 100% |

### 6.4 판정 기준
- Critical Task 중 Severity = Critical인 항목: 통과율 100% 필수 (1건이라도 실패 시 설계 변경 후 재평가)
- Severity = Serious인 항목: 통과율 ≥90%, 미통과 건의 근본원인 분석 및 잔존위험 수용 판정 필요

## 7. 사용오류 ↔ 위험관리 연계 (ISO 14971)

### 7.1 연계 흐름
```
Use Error 식별 (§5.3)
  → Hazardous Situation 발생 가능성 평가
  → Harm Severity × Probability 평가
  → 위험통제 조치 결정:
       ① 본질안전설계 (Inherent Safety by Design)
            예: 최대 mAs 하드웨어 제한, 소아 잠금 모드
       ② 보호조치 (Protective Measures)
            예: 이중 확인 다이얼로그, Interlock, AEC Override 경고
       ③ 정보안전 (Information for Safety)
            예: 선량 표시, 방사선 경고 레이블, 사용자 매뉴얼
  → Summative 평가에서 잔존위험 검증
  → 위험관리 보고서에 UE 결과 통합
```

### 7.2 위험통제 후 잔존위험 판정
- 잔존위험이 수용 가능 수준 이내: 문서화 → 경영진 수용 결정
- 잔존위험이 수용 불가: 설계 변경 → UE 프로세스 재진입 (Formative부터)

## 8. AI 인터랙션 추가 요구사항

### 8.1 EU AI Act / 디지털의료제품법 대응

AI 진단보조 결과 표시 UI는 다음 정보를 동일 화면에 제시해야 한다:

| 요구사항 | 근거 | UI 구현 방안 |
|---------|------|------------|
| 모델 버전·학습 데이터 출처 | EU AI Act Art.13 | 정보 패널 (접이식) |
| Confidence Interval / 위험도 분포 | Art.13 | 수치 + 색상 코드 바 |
| 설명성 시각화 (Saliency/Heatmap) | Art.13, MFDS 가이드 | 영상 오버레이 (토글) |
| 사용자 수용/거부 입력 필수 | Art.14 인간감독 | 명시적 버튼 (기본값 없음) |
| 수용/거부 근거 기록 | 디지털의료제품법 | 구조화 입력 (드롭다운+자유텍스트) |

### 8.2 Automation Bias 평가 시나리오
- Summative CT-07 평가 시 다음 시나리오 포함:
  - AI가 위양성 결과를 표시하는 케이스 (의사가 거부해야 정답)
  - AI가 위음성 결과를 표시하는 케이스 (의사가 자체 판단으로 양성 판정해야 정답)
  - 통과 기준: 위양성 거부율 ≥80%, 위음성 자체 발견율 ≥70%

### 8.3 합성 이미지 관련 (해당 시)
- EU AI Act Art.50: 생성형 AI 출력물 워터마크 가시성 평가 (해당 시에만)
