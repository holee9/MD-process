## 3. 프로세스 단계별 산출물·판정기준

### 3.1 위험관리 계획 (Clause 4.4)

**필수 요소:**
- 적용 범위(제품·구성·수명주기 단계)
- 역할·책임(R&D, RA, QA, PMS, PRRC 연계)
- 위험 수용 기준 (조직 정책 기반, 객관적 근거 필요)
- 검증 활동 및 결과 편익-위험 분석 방법
- 시판후 정보 수집·검토 주기

**X-ray 시스템 특화 고려:**
- 방사선량 한계 (환자·종사자 선량 기준)
- 고전압·전자파(EMC) 안전
- 영상 신뢰도 (아티팩트, 해상도, AI 보조진단 정확도)
- 사이버보안 위협 (DICOM/네트워크 취약점)
- AI/ML 성능 드리프트 모니터링

**판정기준:** 품질책임자(QMR) 또는 PRRC 서명 승인. 위험 수용 기준이 경영진 승인 정책과 정합하지 않으면 반려.

### 3.2 위험 분석 (Clause 5)

| 단계 | 활동 | 산출물 | X-ray 적용예시 |
|------|------|--------|---------------|
| 5.2 | Intended Use 기술 | IU Statement | 성인/소아 진단촬영, 투시, 이동형 수술장 사용 |
| 5.3 | 안전특성 식별 | TR 24971 Annex A 체크리스트 | 방사선, 전기, 기계, SW, 생체적합성, EMC |
| 5.4 | 위해요인 식별 | Hazard List | RAD-01~05, EM-01~03, SW-01~04, UE-01~02 |
| 5.5 | 위험 추정 | 위해요인 분석표 (F-RM-001) | S/P 등급 부여, 초기 위험등급 산출 |

**P(발생가능성) 분해 원칙:**
- P1: 위험상황(Hazardous Situation) 발생 확률
- P2: 위험상황 → 위해(Harm) 전이 확률
- P = P1 × P2 → 위험 매트릭스의 P 등급으로 변환

### 3.3 위험 평가 (Clause 6)

평가 매트릭스는 `위험관리_개요.md §3`의 5×5 매트릭스 적용.

**판정 결과별 후속 조치:**

| 등급 | 판정 | 후속 조치 | 문서화 요건 |
|------|------|-----------|------------|
| U | 수용 불가 | 반드시 위험 저감 후 재평가 | 통제 조치 명세 + 검증 기록 |
| H | ALARP 필요 | 편익-위험 분석 후 조건부 수용 | 편익-위험 분석서 (임상 근거 포함) |
| M | ALARP 검토 | 저감 가능 여부 검토, ALARP 입증 | ALARP 검토 기록 |
| L | 수용 가능 | 잔여위험으로 기록, PMS 모니터링 | F-RM-001 잔여위험 란 |

### 3.4 위험 통제 (Clause 7)

**우선순위 원칙:**
1. 본질안전 설계 (Inherent safety by design)
2. 보호수단 (방사선 차폐, 인터록, 하드웨어 리미터, 이중화)
3. 정보 제공 (경고·IFU·교육)

**X-ray 시스템 통제 수단 예시:**

| 위해요인 | ① 본질안전 설계 | ② 보호수단 | ③ 정보 제공 |
|----------|----------------|------------|-------------|
| RAD-01 과출력 | AEC 알고리즘 최적화 | SW 리미터, 인터록 | 선량 표시, 과노출 경고 |
| EM-01 감전 | 튜브 하우징 밀폐 설계 | 인터록, 접지, 누전차단기 | 고전압 경고표지 |
| SW-02 환자ID 불일치 | Worklist 자동 매칭 | Barcode/RFID 이중확인 | 수동확인 절차 IFU |
| SW-03 사이버공격 | 네트워크 분리 설계 | 암호화, RBAC, 방화벽 | 보안 사용가이드 |
| UE-01 조건 오선택 | 연령별 프리셋 자동추천 | 소아 모드 과노출 차단 | UI 경고, 교육 |

**통제 검증:** 각 통제 조치별 검증 방법(V&V 시험 번호, 시뮬레이션 ID, 분석 참조)을 F-RM-001에 기록. 통제 자체가 새로운 위해를 유발하지 않는지 확인(7.5). 위험 통제 완전성은 §7.6에서 별도 검증.

### 3.5 잔여위험 평가 및 편익-위험 (Cl.7.3 · 7.4 · 8)

**조항 구분 (ISO 14971:2019):**
- §7.3 *Residual risk evaluation* — 통제 조치 적용 후 **개별** 잔여위험을 위험수용 기준에 비추어 평가.
- §7.4 *Benefit-risk analysis* — 개별 잔여위험이 수용 기준을 초과할 때 의료적 편익과 비교하여 정당화.
- §8 *Evaluation of overall residual risk* — 모든 개별 잔여위험의 **합산 효과**를 평가하고 수용성 판정.

모든 통제 후 잔여위험이 수용 기준을 벗어나면 편익-위험 분석(§7.4)으로 정당화.

**편익-위험 분석 입력:**
- 임상평가 결과 (EU MDR CER / FDA Clinical Evidence)
- 유사 기기 데이터 (Predicate Device, Equivalent Device)
- 의학문헌 근거
- State of the Art 기술 수준

**전체 잔여위험(Overall Residual Risk) 평가:**
- 개별 잔여위험 합산 평가 — 상호작용 효과 고려
- 수용 불가 시 추가 통제 또는 설계 변경

### 3.6 위험관리 검토 (Clause 9)

릴리스 전 위험관리 보고서(F-RM-003) 작성. 아래 항목 확인:
- 위험관리 계획의 모든 활동 완료 여부
- 위험관리 파일(RMF) 완전성
- 편익-위험 수용성 최종 판단
- 시판후 정보 수집 계획 운영 준비 확인

### 3.7 생산·시판후 활동 (Clause 10)

| 활동 | 내용 | 주기 | 담당 |
|------|------|------|------|
| 10.1 정보 수집 | PMS, PMCF, 불만, Vigilance, 문헌, 규제 경보 | 상시 | PMS |
| 10.2 정보 검토 | 이전 추정과 비교, 새 위해요인 여부 | 분기 | QA/RA |
| 10.3 조치 | 위험 재평가, 통제 변경, 기술문서 개정 | 사안별 | R&D/QA |
| 10.4 CAPA 환류 | 근본원인 → 위험분석 갱신 → RMF 개정 | 사안별 | QA |

## 4. 수용 기준 설정 가이드 (ISO/TR 24971 §5)

기준 수립 시 고려사항:
- 적용 가능 규제 (MFDS, FDA, EU MDR)
- 관련 국제 표준 (IEC 60601-1 Essential Performance)
- 일반인 위험 인식, 환자·사용자 기대치
- State of the Art 기술 수준

**주의:** "ALARP(As Low As Reasonably Practicable)" 표현은 ISO 14971:2019에서 삭제됨. 조직 고유 수용 기준으로 대체 필요. 본 프로젝트에서는 `위험관리_개요.md §3`의 5×5 매트릭스와 U/H/M/L 4단계 판정 체계를 적용.

### 6.3 위험 수용 기준

위험 수용 기준은 `위험관리_개요.md §3` 매트릭스를 적용하며, 아래를 명시:

| 항목 | 기준 |

## 8. 정량 방법론 선택 지침 (ISO/TR 24971 Annex B)

| 방법 | 용도 | 프로젝트 적용 예 | 산출물 |
|------|------|------------------|--------|
| PHA | 개념 단계 위해 식별 | 제품 기획 초기 | 초기 Hazard List |
| FMEA (기능·설계·공정) | 단일 고장 영향 분석 | detector 센서 고장, 제조 공정 FMEA | FMEA 워크시트 |
| FTA | 복합 원인·최종 위해 추적 | 과노출 시나리오, AEC 고장 복합원인 | Fault Tree Diagram |
| HAZOP | 운영 편차 분석 | 워크플로·사용자 인터랙션 | HAZOP 워크시트 |
| STPA | 시스템 이론 기반 제어 상호작용 | SW·HW 통합 제어 분석(AI/ML 포함) | Control Structure + UCA |

**X-ray 프로젝트 권장 조합:**
- 설계 초기: PHA → 전체 위해요인 도출
- 설계 상세: 설계 FMEA (디텍터, HV Generator, SW) + FTA (과노출 시나리오)
- 제조: 공정 FMEA (조립, 교정, 출하시험)
- SW/AI: STPA (AI 판독 보조 시스템 제어 흐름)
- 사용성: HAZOP + IEC 62366-1 Use Error Analysis

## 9. 사이버보안 위험 통합 (IEC 81001-5-1 + AAMI TIR57)

**보안→안전 위험 변환 경로:**
```
사이버 위협 → 취약점 악용 → 보안 사고 → 안전 영향 평가
  (STRIDE/ATT&CK)         (CIA 영향)    (S/P 재추정)
```

**필수 활동:**
- Threat Modeling (STRIDE 또는 ATT&CK for Medical Devices)
- SBOM 기반 취약점 모니터링 및 패치 영향 재평가
- 보안 위험 → 안전 위험 변환 매핑 문서화
- 시판후 사이버보안 모니터링 → 위험 재평가 트리거
