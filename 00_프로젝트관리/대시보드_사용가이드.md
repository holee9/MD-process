# 대시보드 사용 가이드

## 0. 접근

- **주소(어디서든):** https://holee9.github.io/MD-process/ (GitHub Pages, 매 push 자동 갱신)
- **Cowork 핀:** 본인 PC 사이드바 Pinned 대시보드(동일 내용 동기화)

## 1. 사실성·신뢰도 패널 (최상단 — 핵심)

독립 감사관이 빌더 산출물을 1차 출처로 재검증한 결과. **매일 가장 먼저 볼 곳.**

- **최신 표본 사실 통과율** — 추세가 중요(하루 단위로 출렁임이 정상). 일주일 추세와 *재감사 통과*가 진짜 신뢰 신호.
- **열린 사실오류(audit P0)** — 미수정 사실오류. **0 유지가 건강 게이트.** >0이 지속되면 루프가 막힌 것.
- **누적 발견 사실오류 / 누적 검증 주장 / 감사결함 수정완료 / 누적 통과율.**
- **회차 추세 차트** — 점에 마우스를 올리면 그 **회차(날짜·표본 문서수·검증 주장·사실오류)**가 표시.
  - 통과율 = (검증주장 − 사실오류 − 인용결함) / 검증주장.

## 2. 3소스 이슈 백로그

빌더가 무엇을 작업/대기 중인지. 우선순위 **audit P0 > emergent P0 > plan P1···**.
- audit(감사 결함, 최우선) / plan(조항완전성 전략 갭) / emergent(실행 중 자가발견).

## 3. 사람 점검 (주간/월간 — 트리거 기반)

평소엔 조용하고 트리거가 걸릴 때 사람이 결정할 항목을 띄운다.
- **주간:** 통과율 추세 하락 / 열린 audit P0 지속 / 해석범위·미확인(RA 판단).
- **월간:** 표본 누적 충분 → 정식 게이트 재채점 / 조항완전성 천장 근접 → 엔진 완성·조직통합 판단.

## 4. 이슈 등록 폼 (Git 몰라도 OK)

하단 폼에서 **칸을 채우고 제출 1번**으로 표준 템플릿 이슈가 생성된다.
- **필수(*):** 작성자(이름/역할) · 유형 · 대상/주제 · 내용 — 채워야 등록된다.
- **선택:** 우선순위(유형별 자동 기본값) · 관련 근거(URL).
- **유형**을 고르면 바로 아래에 그 유형 설명이 자동 표시된다(주간점검·집중지시·RA유권해석·발생결함·일반).
- 제출 시 GitHub 로그인+제출이 필요하다(누가 등록했는지 추적성 확보). 작성자·라벨이 자동 포함된다.

## 5. 보기 링크(🔗)

읽기 전용 — 열린 사실오류 / plan 백로그 / 감사 로그(`_audit_log.md`)로 바로 이동.

## 6. 권한

- **등록(쓰기):** GitHub 로그인 + 저장소 이슈 권한 필요. 협업자는 저장소 collaborator로 추가.
- **보기(읽기):** 공개 저장소면 로그인 불필요. (사내 Gitea 이전 시 보기도 사내 인증 필요 — 기밀 통제문서에 적합)

## 7. 차수별 번호 구분(혼동 주의)

- **N회차** = 감사 사이클(추세 차트 x축).
- **#900~** = 감사가 찾은 개별 결함 이슈 번호(특정 문서의 특정 사실오류).
