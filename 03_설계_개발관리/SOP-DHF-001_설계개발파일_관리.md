## 1. 목적

본 절차는 의료용 X-ray 시스템(generator, tube, collimator, detector, 제어 SW, AI 영상처리 구성요소 포함) 각 모델에 대한 **설계개발파일(DHF: Design History File / ISO 13485 용어: DDF: Design and Development File)** 의 구성·인덱스 관리·버전 통제·완전성 점검·이관 트리거·폐기 절차를 정의한다.

목표:

1. ISO 13485:2016 §7.3.10이 요구하는 설계개발 활동 증적(Evidence)의 완전·정확한 파일 유지
2. FDA QMSR §820.10(c) → ISO 13485:2016 §7.3.10 (DHF) 요건 — 설계이력이 승인된 기기마스터기록(DMR)에 따라 개발되었음을 입증
3. EU MDR Annex II 기술문서의 DHF 파트 완전성 보장
4. 규제기관 실사(Audit/Inspection) 시 즉각 제출 가능한 인덱스 기반 파일 체계 운영

- 신규 제품 개발(PHase 1 기획 개시 시점부터 이관 완료 후 아카이브까지 전 기간)

**제외:** Class I 경미 변경(Minor Change), 제조공정 중 검사기록(DHR — Device History Record), 규제 제출용 기술문서 외형 편집

## 4. 용어 정의

| 용어 | 정의 |
|------|------|
| DHF (Design History File) | FDA QMSR §820.10(c) → ISO 13485:2016 §7.3.10 용어. 설계개발 이력 기록 파일 전체. ISO 13485 §7.3.10 DDF와 동등 |
| DDF (Design and Development File) | ISO 13485:2016 §7.3.10 공식 용어. 본 SOP에서는 DHF/DDF 혼용 허용 |
| DMR (Device Master Record) | 기기마스터기록 — 제조에 필요한 모든 사양·절차·허용기준 (SOP-DT-001 참조) |
| DHR (Device History Record) | 기기이력기록 — 각 생산 단위/로트의 제조이력 (별도 관리, DHF 아님) |
| DHF 인덱스 | DHF를 구성하는 모든 문서·기록 목록 (문서ID, 버전, 상태, 위치 포함) |
| 완전성 점검 | DHF 인덱스 항목의 존재·버전·서명·내용 적합성 확인 활동 (CHK-DHF-001 사용) |
| 이관 트리거 | DHF를 DR5(최종 설계검토)·설계이관(SOP-DT-001) 완료 후 아카이브 상태로 전환하는 조건 |
| 아카이브 | 제품 단종 후 최소 보존 기간 동안의 불변(Immutable) 보관 상태 |

## 7. 절차 세부 설명

### 7.1 DHF 개설

**트리거:** 제품 개발 기획(Phase 1 착수 승인, CHK-DR-001 DR0 Gate 통과)

**입력물:**
- DR0 게이트 의사결정 기록
- 제품 요구사항 초안 (URS/PRD)
- 제품코드 부여 공문

**수행 단계:**

1. 설계개발 Lead는 DHF-ID를 `DHF-[제품코드]-[연도]` 형식으로 부여 (예: `DHF-XRAY-DR-001-2026`)
2. F-DHF-001 **DHF 인덱스** 문서를 eDMS에 신규 생성; 다음 메타데이터 기록:
   - DHF-ID, 제품명, 모델코드, IVD/Non-IVD 구분, 인허가 국가, 위험등급
   - 담당 설계개발 Lead, QA Manager 지정
   - 개설일, 예상 이관 목표일
3. 인덱스 섹션 뼈대 생성 (§7.2 참조)
4. eDMS 상태 → "Active — Development"

**출력물:** F-DHF-001 초기본 (eDMS 등록 확인)

**판정 기준:** DHF-ID 부여 + eDMS 등록 완료 시 개설 확인

---

### 7.2 DHF 인덱스 구조 (필수 섹션)

DHF는 다음 8개 섹션으로 구성된다. 각 섹션에 해당 문서ID·버전·위치·승인상태를 기록한다.

| 섹션 | 내용 | 규제 근거 | X-ray 적용 예시 |
|------|------|-----------|-----------------|
| **A. 기획·요구사항** | 개발 계획, 제품 요구사항(URS/PRD), 위험등급 판정, 의도된 사용 | ISO 13485 §7.3.2, §7.3.3 | DR0 Gate 기록, X-ray 의도된 사용 명세, IEC60601-2-54 적용 범위 결정 |
| **B. 설계 입력물** | 기능·성능·안전·규제 요구사항 목록 (설계 입력물 매트릭스) | ISO 13485 §7.3.3 | 이미지 SNR, 선량, 촬영 속도, IEC 60601-2-54 §201.4 요구, ALARA 요건 |
| **C. 설계 출력물** | 사양서, 도면, BOM, SW 아키텍처, 인터페이스 명세 | ISO 13485 §7.3.4 | 시스템 블록도, HW 도면, FW 소스코드 버전, AI 모델 버전 사양 |
| **D. 설계 검토 기록** | DR0~DR5 각 Gate 회의록·체크리스트·부적합 목록 | ISO 13485 §7.3.5, CHK-DR-001 | DR1(콘셉트), DR2(예비), DR3(상세), DR4(V&V), DR5(최종) |
| **E. 설계 검증 기록** | 시험 계획·보고서, 계산서, 시뮬레이션 결과 | ISO 13485 §7.3.6 | IEC 60601-2-54 형식시험, 전자기적합성(EMC), ALARA 성능시험 |
| **F. 설계 밸리데이션 기록** | 사용자 시험, 임상평가 결과, 사용적합성 평가 | ISO 13485 §7.3.7, IEC 62366-1 | 방사선사 대상 사용성 평가(IEC 62366-1 §5.9), 임상 성능 평가 |
| **G. SW·AI 파일** | IEC 62304 개발 계획·구성관리·릴리스·아카이브 기록, SBOM, AI 거버넌스 | IEC 62304 §5.1, §8; SOP-SBOM-001, SOP-AIGOV-001 | SW 수명주기 계획, FW 릴리스 노트, SBOM v2.0, AI 모델 카드 |
| **H. 위험관리 파일** | 위험관리 계획·보고서·FMEA·잔여위험 수용 기록 | ISO 14971 §7; SOP-RM-001 | X-ray 선량 위험 FMEA, 전기안전 위험 분석, AI 오진단 위험 |
| **I. 이관·변경 기록** | 설계이관 보고서(DTR), 변경 이력 (Class II/III) | ISO 13485 §7.3.8, §7.3.10, SOP-DT-001 | DTR-XRAY-DR-001-2026, CC-001 변경 기록 |

> **노트:** 위험관리 파일(H)은 ISO 14971 §7에 따라 독립 유지도 허용되나, 반드시 DHF 인덱스에서 참조 위치(파일명·버전)를 명시해야 한다.

### 7.3 SW/AI 섹션 (G) 특기 사항

IEC 62304 §8(SW 구성관리) 및 §5.1(SW 개발계획) 요구에 따라 SW/AI 섹션에는 다음을 포함해야 한다:

1. **SW 항목 목록 (Software Item List):** 모듈명·버전·분류(Class A/B/C)·담당자
2. **SBOM (Software Bill of Materials):** SOP-SBOM-001에 따른 SBOM 파일 버전 및 위치
3. **SW 릴리스 노트:** 각 FW/SW 버전별 변경 내역, 빌드 환경, 배포 방법
4. **SW 결함 목록·해결 기록:** IEC 62304 §6.2 버그 추적 기록
5. **AI/ML 모델 버전 기록:** SOP-AIGOV-001의 모델 카드(Model Card) 참조 위치, 데이터셋 버전(SOP-AIDATA-001 참조)
6. **사이버보안 기록:** IEC 81001-5-1 §6 위협 모델링, 취약점 평가 보고서 (SOP-SBOM-001 연계)

### 7.4 TF-TD-001 기술문서와의 구분·연계

| 항목 | DHF (SOP-DHF-001) | 기술문서·의료기기파일 (TF-TD-001) |
|------|------------------|----------------------------------|
| 목적 | 설계개발 **이력** 기록 (How it was designed) | EU MDR Annex II/III 기술문서, 규제 제출용 |
| 내용 | 개발 과정 전 증적(Evidence) | 현재 승인된 설계 상태 설명 |
| 관리 주체 | 설계개발 Lead + QA | RA Manager + QA |
| 실사 제출 대상 | FDA DHR, MFDS 현장 실사 | EU/국내 인허가 제출, Notified Body |
| 참조 관계 | DHF는 기술문서의 상세 근거 제공 | 기술문서는 DHF 특정 항목을 요약·인용 |

**연계 규칙:** 기술문서(TF-TD-001)가 DHF 항목을 인용할 때는 `DHF-ID/섹션/문서ID/버전`을 명시한다. DHF는 기술문서를 직접 포함하지 않으며 참조 위치만 기록한다.

### 7.5 완전성 점검 (CHK-DHF-001)

**수행 시점:** (1) 설계이관 직전(DR5 게이트 통과 전), (2) 주요 설계변경 완료 시, (3) 연간 DHF 상태검토(정기)

**수행자:** QA Manager (독립 검토자)

**판정 기준:**

| 판정 | 기준 | 후속 조치 |
|------|------|-----------|
| 완전 (Pass) | 모든 필수 항목 존재·승인·최신 버전 확인 | DHF 승인·이관 진행 |
| 조건부 완전 | 경미 결함 1~3건 (내용 오기·위치 오류·서명 미완) | 30일 내 보완 후 재점검 |
| 미완전 (Fail) | 필수 섹션 누락 또는 미승인 결과물 | DR5 진행 보류, 설계개발 Lead에 시정 요청 |

CHK-DHF-001 체크리스트는 §9에 정의한다.

### 7.6 이관 트리거 및 아카이브 전환

**이관 트리거 조건 (전부 충족 필요):**

- [ ] CHK-DHF-001 완전성 점검 → Pass 판정
- [ ] CHK-DR-001 DR5(최종 설계검토) 승인 완료
- [ ] SOP-DT-001 설계이관 보고서(DTR) 최종 승인 완료
- [ ] 위험관리 보고서(SOP-RM-001) 잔여위험 수용 서명 완료
- [ ] 모든 열린 설계 부적합(Non-Conformance) 종결 확인

**아카이브 전환 절차:**

1. 설계개발 Lead + QA Manager 공동 서명 (F-DHF-001 최종 서명란)
2. eDMS 상태 → "Archived" 변경 (편집 잠금 활성화)
3. 아카이브 일자, 최종 버전 번호 기록
4. TF-TD-001 기술문서의 DHF 참조 항목 갱신

### 7.7 설계변경 시 DHF 관리

SOP-CC-001에 따라 **Class II(주요 변경)** 또는 **Class III(새 제품 해당) 변경**으로 판정된 경우:

1. 기존 DHF는 변경 전 상태로 **불변 유지** (eDMS 이력 보존)
2. DHF 내 **변경 섹션(Change History)** 추가; 변경 번호(CC-ID), 변경 사유, 영향받은 섹션 기록
3. 변경 영향받은 섹션(A~I) 재검토·갱신; 미영향 섹션은 "변경 없음" 명시
4. CHK-DHF-001 재수행 → 완전성 재확인
5. 변경 완료 후 Step 7.6 이관 트리거 재확인

**Class I(경미 변경):** DHF 내 `Minor Change Log` 항목 추가로 갈음; 완전성 점검 불필요.
