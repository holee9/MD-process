## 1. 목적

본 워크시트는 의료용 X-ray 시스템(평판 디텍터, 진단 소프트웨어 포함)에 대해 **FMEA(Failure Mode and Effects Analysis)** 를 체계적으로 수행하기 위한 양식과 기준을 정의한다. ISO 14971:2019 위험 분석(Clause 5) 및 IEC 60812:2018 FMEA 방법론에 따르며, 설계(dFMEA), 공정(pFMEA), 사이버보안, AI/ML, 사용오류 영역을 포괄한다.

## 2. 적용 범위

| 구분 | 적용 대상 | FMEA 유형 |
|------|-----------|-----------|
| 하드웨어 | X-ray 튜브, HV Generator, 평판 디텍터, 콜리메이터, 기구부 | 설계 FMEA (dFMEA) |
| 소프트웨어 | 영상 획득 SW, DICOM 통신, AI/ML 모듈, AEC 제어 | 설계 FMEA + AI/ML FMEA |
| 제조공정 | 디텍터 본딩, X-ray 조립, HV 절연시험, 교정, 출하검사 | 공정 FMEA (pFMEA) |
| 사이버보안 | 네트워크 인터페이스, DICOM/HL7, 인증/접근통제, SBOM | 사이버보안 FMEA |
| 사용자 인터페이스 | 촬영 조건 선택, 환자 ID 확인, 비상정지, 선량 표시 | 사용오류 FMEA |

## 3. 용어 정의

| 용어 | 정의 | 비고 |
|------|------|------|
| 고장모드 (Failure Mode) | 기능·구성요소가 의도된 기능을 수행하지 못하는 방식 | IEC 60812 §3.2 |
| 고장영향 (Failure Effect) | 고장모드가 시스템·환자·사용자에 미치는 결과 | 로컬/최종 영향 구분 |
| 고장원인 (Failure Cause) | 고장모드를 유발하는 근본 원인 | |
| 심각성 (Severity, S) | 고장영향의 최악 결과에 대한 등급 | 위험관리_개요.md §3.1 |
| 발생도 (Occurrence, O) | 고장원인이 발생할 가능성 등급 | 본 문서 §4.2 |
| 검출도 (Detection, D) | 현재 통제 수단으로 고장을 출하 전 검출할 가능성 등급 | 본 문서 §4.3 |
| RPN | Risk Priority Number = S x O x D | IEC 60812 참고 |
| AP (Action Priority) | 조치 우선순위 (H/M/L) — AIAG-VDA FMEA 기반 | 본 문서 §4.4 |

## 4. 평가 기준

### 4.1 심각성(Severity) 등급 — S

위험관리_개요.md §3.1과 정합. FMEA 분석 시 아래 10점 척도를 병행 사용한다.

| S 등급 | 점수 | 설명 | ISO 14971 매핑 | X-ray 시스템 예시 |
|--------|------|------|---------------|------------------|
| S1 | 1 | 영향 없음 | - | 로그 기록 누락 (안전 무관) |
| S2 | 2-3 | 사소한 불편 | S1 (Negligible) | 영상 표시 지연, UI 깜빡임 |
| S3 | 4-5 | 기능 저하, 재촬영 필요 | S2 (Minor) | 영상 아티팩트, 경미한 노출 변동 |
| S4 | 6-7 | 진단 정확도 저하 또는 규정 한도 이내 과노출 | S3 (Serious) | AEC 오산출, 선량 표시 오류 |
| S5 | 8 | 입원 필요한 수준의 위해 | S4 (Critical) | 단일 과노출 (규정 초과) |
| S6 | 9 | 영구 장해 또는 생명 위협 | S4 (Critical) | 반복 과노출, 차폐 실패 |
| S7 | 10 | 사망 가능 | S5 (Catastrophic) | 고전압 감전, 극심한 피폭 |

### 4.2 발생도(Occurrence) 등급 — O

| O 등급 | 점수 | 발생 빈도 기준 | ISO 14971 매핑 |
|--------|------|---------------|---------------|
| O1 | 1 | 극히 드묾 (< 1/1,000,000) | P1 |
| O2 | 2-3 | 매우 낮음 (1/100,000 ~ 1/1,000,000) | P2 |
| O3 | 4-5 | 낮음 (1/10,000 ~ 1/100,000) | P2-P3 |
| O4 | 6-7 | 보통 (1/1,000 ~ 1/10,000) | P3 |
| O5 | 8 | 높음 (1/100 ~ 1/1,000) | P4 |
| O6 | 9-10 | 매우 높음 (> 1/100) | P5 |

### 4.3 검출도(Detection) 등급 — D

| D 등급 | 점수 | 설명 | 검출 방법 예시 |
|--------|------|------|---------------|
| D1 | 1 | 거의 확실히 검출 | 자동 인터록으로 즉시 차단 |
| D2 | 2-3 | 높은 검출 확률 | 자동 SW 시험 + 출하 전 전수검사 |
| D3 | 4-5 | 보통 검출 확률 | 표본 검사, 주기적 교정 시험 |
| D4 | 6-7 | 낮은 검출 확률 | 필드 사용 중 사용자 인지 의존 |
| D5 | 8-9 | 매우 낮은 검출 확률 | 간접 증상으로만 추정 |
| D6 | 10 | 검출 불가능 | 누적 고장, 잠재 결함 |

### 4.4 조치 우선순위(Action Priority, AP) 판정 기준

RPN(S x O x D) 단독이 아닌, AIAG-VDA FMEA 방식의 AP를 병행 적용한다.

| AP 등급 | 조건 | 필요 조치 |
|---------|------|-----------|
| **H (High)** | S >= 8, 또는 RPN >= 200, 또는 ISO 14971 위험등급 U/H | 즉시 위험 저감 조치 필수. 설계변경 또는 추가 보호수단 |
| **M (Medium)** | S >= 6 이고 O >= 4, 또는 RPN 100-199 | 위험 저감 조치 권고. ALARP 검토 문서화 |
| **L (Low)** | 상기 조건에 해당하지 않음 | 현 상태 수용. 모니터링 지속 |

> **참고:** AP 판정 결과는 ISO 14971 위험 매트릭스(위험관리_개요.md §3.3)의 U/H/M/L 판정과 교차 확인하여 최종 위험등급을 결정한다.

## 6. 공정 FMEA (pFMEA) 워크시트

### 6.1 개요

공정 FMEA는 제조·조립·검사 공정에서 발생할 수 있는 고장모드를 분석하여 최종 제품의 안전성·성능에 미치는 영향을 평가한다. IEC 60812:2018 및 AIAG-VDA pFMEA 방법론을 준용한다.

### 6.2 pFMEA 양식

| No. | 공정단계 | 공정 기능 | 고장모드 | 고장영향 (공정) | 고장영향 (최종 제품) | S | 고장원인 | 현재 공정통제 (예방) | O | 현재 공정통제 (검출) | D | RPN | AP | 권고 조치 | 조치 결과 | 잔여S | 잔여O | 잔여D | 잔여RPN | 잔여AP | 상태 | 담당 |
|-----|---------|-----------|----------|----------------|---------------------|---|----------|---------------------|---|---------------------|---|-----|----|-----------|-----------|----|----|----|---------|--------|------|------|
| | | | | | | 1-10 | | | 1-10 | | 1-10 | | H/M/L | | | | | | | H/M/L | Open/Closed | |

## 7. 사이버보안 FMEA 워크시트 (IEC 81001-5-1 / AAMI SW96)

### 7.1 개요

사이버보안 FMEA는 보안 위협(Threat), 취약점(Vulnerability), 공격벡터(Attack Vector)를 체계적으로 분석하고, 보안 사고가 환자 안전에 미치는 영향을 ISO 14971 위험관리와 통합하여 평가한다.

**보안-안전 위험 변환 경로:**
```
위협 식별 → 취약점 매핑 → 공격 시나리오 → 보안 영향(CIA) → 안전 영향(S/P) → 위험등급
 (STRIDE)    (CVE/SBOM)    (ATT&CK)      (기밀성/무결성/가용성)  (ISO 14971)
```

### 7.2 사이버보안 FMEA 양식

| No. | 자산/인터페이스 | 위협 (STRIDE) | 취약점 | 공격벡터 | 보안영향 (CIA) | 안전영향 (환자/사용자) | S | 공격 실현가능성 | O | 현재 보안통제 | D | RPN | AP | 권고 보안조치 | 조치 결과 | 잔여S | 잔여O | 잔여D | 잔여RPN | 잔여AP | 상태 |
|-----|---------------|--------------|--------|----------|--------------|---------------------|---|---------------|---|-------------|---|-----|----|-----------|-----------|----|----|----|---------|--------|------|
| | | S/T/R/I/D/E | | | C/I/A | | 1-10 | | 1-10 | | 1-10 | | H/M/L | | | | | | | H/M/L | |

**STRIDE 위협 분류:**
- **S** (Spoofing) — 신원 위조
- **T** (Tampering) — 데이터 변조
- **R** (Repudiation) — 부인
- **I** (Information Disclosure) — 정보 노출
- **D** (Denial of Service) — 서비스 거부
- **E** (Elevation of Privilege) — 권한 상승

**공격 실현가능성 평가 요소 (CVSS 기반):**

| 요소 | 높음 (O 7-10) | 중간 (O 4-6) | 낮음 (O 1-3) |
|------|-------------|-------------|-------------|
| 공격 복잡도 | 낮음 (스크립트 키디) | 중간 (전문지식 필요) | 높음 (고급 공격) |
| 접근 경로 | 원격 (인터넷) | 인접 네트워크 | 물리적 접근 필요 |
| 권한 요구 | 없음 | 일반 사용자 | 관리자 |
| 사용자 상호작용 | 불필요 | 일부 필요 | 적극적 참여 필요 |

## 9. 사용오류 FMEA 워크시트 (IEC 62366-1 연계)

### 9.1 개요

사용오류 FMEA는 사용자 인터페이스에서 발생할 수 있는 사용오류(Use Error)가 위험상황(Hazardous Situation)을 유발하는 경로를 분석한다. IEC 62366-1:2015+A1:2020 사용적합성 엔지니어링과 연계하여 수행한다.

**사용오류 발생 경로:**
```
UI 설계 특성 → 사용오류(Use Error) → 위험상황(Hazardous Situation) → 위해(Harm)
              |
     인지적·지각적·행동적 원인
```

### 9.2 사용오류 FMEA 양식

| No. | 사용 시나리오 | UI 요소/기능 | 사용오류 유형 | 인지/지각/행동 원인 | 위험상황 | 잠재적 위해 | S | 오류 발생가능성 | O | 현재 UI 통제 | D | RPN | AP | 권고 UI 개선 | 조치 결과 | 잔여S | 잔여O | 잔여D | 잔여RPN | 잔여AP | IEC 62366-1 참조 | 상태 |
|-----|-------------|-------------|-------------|-------------------|----------|------------|---|---------------|---|-------------|---|-----|----|-----------|-----------|----|----|----|---------|--------|----------------|------|
| | | | 지각/인지/행동 | | | | 1-10 | | 1-10 | | 1-10 | | H/M/L | | | | | | | H/M/L | | |

**사용오류 유형 분류:**
- **지각 오류 (Perception Error):** 정보를 인지하지 못함 (표시 미확인, 경보 미인지)
- **인지 오류 (Cognition Error):** 정보를 잘못 해석 (의미 오해, 판단 착오)
- **행동 오류 (Action Error):** 잘못된 조작 실행 (오선택, 미스터치, 순서 오류)

## 12. FMEA 작성 지침

### 12.1 공통 규칙

1. **위해요인 ID 체계:** 카테고리 접두사를 사용한다.

| 접두사 | 카테고리 | FMEA 유형 |
|--------|---------|-----------|
| HAZ-RAD- | 방사선 위해 | dFMEA |
| HAZ-EM- | 전기·기계 위해 | dFMEA |
| HAZ-SW- | 소프트웨어 위해 | dFMEA |
| HAZ-CYB- | 사이버보안 위해 | 사이버보안 FMEA |
| HAZ-AI- | AI/ML 위해 | AI/ML FMEA |
| HAZ-USE- | 사용오류 위해 | 사용오류 FMEA |
| pFMEA- | 제조공정 위해 | pFMEA |
| HAZ-BIO- | 생체적합성 위해 | dFMEA |

2. **통제 수단 우선순위:** ISO 14971 Clause 7의 3단계 우선순위를 준수한다.
   - 1순위: 본질안전 설계 (Inherent safety by design)
   - 2순위: 보호수단 (인터록, 차폐, 이중화, SW 리미터)
   - 3순위: 안전 정보 제공 (경고, IFU, 교육)

3. **검증 추적성:** 각 통제 조치에 대해 검증 방법 및 시험 번호(V&V ID, 시험 프로토콜 ID)를 명시한다.

4. **잔여위험 H 이상 시:** 반드시 편익-위험 분석서와 연계하고, §10 종합평가에 반영한다.

5. **신규 위해 확인:** 위험 통제 조치가 새로운 위해요인을 유발하는지 확인하고, 유발 시 해당 위해요인을 별도 항목으로 추가 분석한다 (ISO 14971 Clause 7.5).

6. **위험 통제 완전성 확인:** 모든 식별된 위해요인에 대해 위험 통제 조치가 계획·구현·검증되었는지 완전성을 확인한다 (ISO 14971 Clause 7.6). §10 종합평가 전 필수 게이트로 운용한다.

| FMEA 유형 | 주의사항 |

| dFMEA | 단일 고장 조건(Single Fault Condition) 분석 의무 (IEC 60601-1 §4.7). Essential Performance 영향 평가 포함 |
| pFMEA | 특수공정(본딩, 납땜, 멸균 등)은 공정 밸리데이션(04_제조/공정_밸리데이션.md) 결과와 연계 |
| 사이버보안 | SBOM 기반 취약점(CVE) 목록 정기 갱신. IEC 81001-5-1 §5.7 보안 시험 결과 반영(5.7.1 SECURITY requirements testing 등, audit #982 정정 — §5.5는 구현·검증 단계이며 시험은 §5.7) |
| AI/ML | SOP-AIGOV-001의 드리프트 모니터링·재학습 절차와 연계. IEC 62304 SW 안전등급 결정에 입력 |
| 사용오류 | IEC 62366-1 사용적합성 시험(Formative/Summative) 결과를 D(검출도) 평가에 반영 |

### 12.3 FMEA 갱신 트리거

아래 사건 발생 시 해당 FMEA를 갱신한다.

| 트리거 | 갱신 범위 | 책임 |
|--------|----------|------|
| 설계 변경 (ECO/ECN) | 해당 하위시스템 dFMEA | R&D |
| 공정 변경 (공정 밸리데이션 재수행 시) | 해당 공정 pFMEA | 제조 엔지니어링 |
| SW 업데이트 / AI 모델 재학습 | 해당 SW/AI FMEA | R&D SW팀 / AI팀 |
| 사이버보안 취약점 공개 (CVE) | 사이버보안 FMEA | 보안담당 |
| 사용적합성 평가 결과 (Use Error 신규 발견) | 사용오류 FMEA | UX팀 |
| PMS/Vigilance에서 신규 위해요인 식별 | 전체 해당 FMEA | QA/PMS |
| 규제 요건 변경 | 전체 해당 FMEA | RA |
