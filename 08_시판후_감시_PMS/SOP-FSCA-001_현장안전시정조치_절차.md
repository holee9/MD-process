# SOP-FSCA-001 현장안전시정조치(FSCA) 절차 v0.2

## 1. 목적

본 절차는 자사 의료기기(의료용 X-ray system / detector / SW)가 시판 후 안전 문제를 야기하거나 야기할 수 있는 경우, 현장안전시정조치(Field Safety Corrective Action, FSCA)를 체계적으로 개시·실행·보고·종결하기 위한 절차를 규정한다.

## 2. 적용 범위

- 자사가 제조·출하한 모든 의료기기 및 SW
- 국내(MFDS), 미국(FDA), 유럽(EU MDR) 시장에 유통된 제품
- OEM·위탁제조 포함(공급자 기원 결함 포함)

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| FSCA | 안전상 이유로 시판 중인 의료기기에 대해 제조자가 취하는 시정조치 |
| FSN (Field Safety Notice) | FSCA 관련 사용자·환자 대상 안전 공지문 |
| 중대한 이상사례 (Serious Incident) | 사망, 건강상태의 심각한 악화, 공중보건 위협을 초래하거나 초래할 수 있었던 사건 |
| Correction | 시판 중인 기기의 수리·조정·라벨 변경·폐기·설계 변경 등 |
| Removal | 시판 중인 기기의 시장 회수 |
| Trend Report | 통계적으로 유의미한 이상사례 증가 추세 보고 |
| MIR (Manufacturer Incident Report) | EU MDR 상 제조자 사고 보고서 (v7.3.1, 2026.5 의무화) |
| Advisory Notice(권고공지) | FSCA를 수반하지 않으면서 사용자·환자에게 안전 관련 정보를 제공하는 통지. 예: 사용상 주의사항 보완, 추가 교육·훈련 안내 등 (MDCG 2023-3 Rev.2 §2.4 참조) |

## 4. 책임과 권한

| 역할 | 책임 |
|------|------|
| RA/QA Lead | FSCA 개시 결정, 규제기관 보고 총괄, FSN 승인 |
| PMS 담당자 | 이상사례 접수·분석, FSCA 필요성 평가, 추적 관리 |
| 설계개발팀 | 근본원인 분석, 기술적 시정조치 방안 수립 |
| 제조/품질팀 | 영향 받는 제품 로트·시리얼 추적, 현장 시정 실행 |
| 경영대표 | 중대 FSCA 승인, 자원 배정 |
| 유럽 AR (Authorized Representative) | EU 회원국 관할 당국 보고 지원 |

## 5. 절차

### 5.1 트리거 및 평가

FSCA 검토 트리거:

1. **이상사례(Adverse Event)** — SOP-PMS-001에 따른 불만 접수·부작용 보고
2. **내부 품질 데이터** — 부적합 트렌드, CAPA 결과, 공정 일탈
3. **외부 정보** — 규제기관 안전성 경보, 유사기기 리콜, 사이버보안 취약점 공개
4. **현장 서비스 피드백** — 서비스 엔지니어 보고

PMS 담당자는 위험관리파일(ISO 14971)을 참조하여 잔류위험 재평가를 수행하고, 아래 기준으로 FSCA 필요성을 판정한다:

- 허용 불가한 위험(Unacceptable Risk) → FSCA 개시
- 허용 가능하나 ALARP 초과 → FSCA 또는 대안 조치 검토
- 허용 가능 → 모니터링 지속, 기록 보관

#### 5.1.1 FSCA 개시 판단 의사결정 흐름도

```
┌──────────────┐
│  사건 접수     │  (이상사례·불만·외부경보·서비스피드백)
└──────┬───────┘
       ▼
┌──────────────┐
│  위험평가      │  ISO 14971 잔류위험 재평가
└──────┬───────┘
       ▼
┌──────────────────┐     아니오     ┌──────────────────┐
│ 중대한 이상사례    │─────────────▶│ 모니터링 지속·기록  │
│ 해당 여부 판정     │              │ (Advisory Notice   │
└──────┬───────────┘              │  검토 가능)        │
       │ 예                        └──────────────────┘
       ▼
┌──────────────────┐     아니오     ┌──────────────────┐
│ 허용 불가 위험     │─────────────▶│ ALARP 범위 내 대안  │
│ (Unacceptable)   │              │ 조치 검토·기록      │
└──────┬───────────┘              └──────────────────┘
       │ 예
       ▼
┌──────────────────┐
│ FSCA 개시 결정    │
└──────┬───────────┘
       ▼
┌──────────────────────────────────────────┐
│          FSCA 유형 결정                    │
├──────────┬──────────┬──────────┬─────────┤
│ 시장회수   │ 현장수정   │ SW 업데이트 │ 추가정보 │
│ (Recall)  │ (Field   │ (Remote   │ 제공     │
│           │  Mod.)   │  Patch)   │ (FSN)   │
└──────────┴──────────┴──────────┴─────────┘
```

**판정 기록:** 위 흐름에 따른 판정 결과는 F-FSCA-001(FSCA 계획서)에 근거와 함께 기록한다.

### 5.2 규제기관 보고 기한

#### 5.2.1 EU MDR (Art.87)

| 사건 유형 | 보고 기한 |
|-----------|-----------|
| 공중보건 심각 위협 | 인지 후 **2일** 이내 |
| 사망 또는 건강의 심각한 악화 | 인지 후 **10일** 이내 |
| 기타 중대한 이상사례 | 인지 후 **15일** 이내 |
| FSCA 사전 보고 | 조치 시행 **전** (긴급 시 예외) |

- EUDAMED MIR form v7.3.1 사용 (2026.5 의무)
- 영향 받는 모든 EU 회원국 관할 당국에 통보

#### 5.2.2 FDA (21 CFR Part 806)

| 보고 유형 | 기한 |
|-----------|------|
| Correction/Removal 보고 | 조치 개시 후 **10 영업일** 이내 |
| 기록만 보관(보고 불요) | 건강 위험이 없는 경미한 위반 |

- FDA MedWatch Form 3500A 또는 eMDR 사용

#### 5.2.3 MFDS (국내)

| 사건 유형 | 보고 기한 |
|-----------|-----------|
| 사망 또는 중대한 이상사례 | 인지 후 **15일** 이내 |
| 회수·리콜 | 결정 후 **지체 없이** |

- 의료기기안심책방(emedi.mfds.go.kr) 전자보고

### 5.3 FSCA 계획 수립

FSCA 개시 결정 시 RA/QA Lead는 다음을 포함한 FSCA Plan(F-FSCA-001)을 작성한다:

1. **영향 범위** — 해당 제품 모델, 로트/배치/시리얼 범호, 출하 지역, 영향 수량
2. **위험 평가 요약** — 위해 시나리오, 발생확률, 심각도, 잔류위험 수준
3. **시정조치 유형**
   - 현장 수정(Field Modification) — FW/SW 업데이트, HW 부품 교체, 재교정
   - 추가 라벨링/IFU 개정
   - 사용 제한/중단 권고
   - 시장 회수(Removal/Recall)
4. **일정** — 규제보고 기한, FSN 배포일, 현장조치 완료 목표일
5. **책임자** — 각 단계별 담당자 및 승인권자
6. **유효성 확인 방법** — 조치 완료율 추적, 재발방지 검증

### 5.4 현장안전공지(FSN) 작성 및 배포

FSN(F-FSCA-002)은 다음 요소를 포함한다:

- 제조자명, 연락처, 날짜
- 영향 받는 기기(모델, UDI-DI, 로트/시리얼)
- 결함 또는 안전 문제 설명
- 환자·사용자 위해 평가
- 사용자가 취해야 할 조치
- 제조자가 취하고 있는 조치
- FSN 배포 범위 및 회신 요청

**언어 요구사항:**
- EU: 해당 회원국 공용어 (EU MDR Art.87(11))
- 미국: 영어
- 국내: 한국어

FSN은 FSCA 시행 **전** 배포를 원칙으로 하되, 환자 안전상 긴급한 경우 동시 배포 허용.

### 5.5 현장 시정 실행

1. 제조/서비스팀은 FSCA Plan에 따라 현장 조치 실행
2. 각 기기별 조치 완료 기록(F-FSCA-003)을 작성
3. 완료율을 주간 단위로 PMS 담당자에게 보고
4. **X-ray 특화 고려사항:**
   - 방사선 출력 관련 결함 시 즉각 사용 중단 권고 우선
   - 디텍터 FW 업데이트 시 DQE/MTF 재검증 포함
   - 선량 표시 오류 시 ALARA 영향 평가 추가
   - 사이버보안 취약점 시 네트워크 격리 조치 선행

### 5.6 SW 관련 FSCA 특수 절차

SW 결함에 의한 FSCA의 경우 아래 추가 절차를 적용한다.

#### 5.6.1 원격 패치 배포 프로세스

1. **패치 개발** — 설계개발팀은 SW 문제 해결 패치를 IEC 62304 §9(Software Problem Resolution) 프로세스에 따라 개발·검증한다.
2. **위험평가** — 패치 자체로 인한 신규 위험(regression risk)을 ISO 14971에 따라 평가한다.
3. **배포 전 검증** — 배포 대상 환경(OS·HW 호환성)에서 integration testing 및 regression testing을 수행한다.
4. **원격 배포 실행** — 원격 업데이트 인프라를 통해 패치를 배포하되, 다음을 준수한다:
   - 배포 전 사용자에게 FSN 또는 업데이트 안내문을 사전 통보
   - 업데이트 중 기기 작동 중단이 환자 안전에 영향을 미치지 않음을 확인
   - 배포 로그(기기 식별, 배포 시각, 성공/실패 상태) 기록
   - 실패 시 rollback 메커니즘 및 수동 업데이트 대안 확보
5. **배포 후 확인** — 패치 적용 완료 여부를 기기별로 추적하고, 미적용 기기에 대한 후속 조치를 수행한다.

#### 5.6.2 IEC 62304 §9 연계

- SW Problem Report → 근본원인 분석 → Change Request(SOP-CC-001) → 패치 개발·검증 → 릴리스
- SW 안전 등급(Class A/B/C)에 따라 검증 수준을 차등 적용
- SW Bill of Materials(SBOM) 업데이트 및 기술문서 반영

#### 5.6.3 사이버보안 긴급 패치 (IEC 81001-5-1 §8.3)

- 사이버보안 취약점(CVE 등)이 FSCA 트리거인 경우, IEC 81001-5-1 §8.3(Security incident response)에 따라 처리
- 긴급도에 따른 패치 배포 기한:
  - **Critical (CVSS ≥9.0)**: 인지 후 72시간 이내 긴급 패치 또는 완화조치 배포
  - **High (CVSS 7.0–8.9)**: 14일 이내
  - **Medium (CVSS 4.0–6.9)**: 정기 업데이트 주기에 포함
- 네트워크 격리 등 임시 완화조치를 패치 배포 전 선행 적용
- 영향 받는 의료기관 IT 부서에 별도 기술 권고문(Technical Advisory) 배포

### 5.7 다중 규제관할권 동시 보고 절차

다수 관할권에 제품이 유통된 경우, 아래 기한 대비표에 따라 동시·병렬 보고를 수행한다.

#### 5.7.1 규제기관별 보고 기한 대비표

| 규제기관 | 보고 유형 | 초기보고 기한 | 후속/최종보고 | 양식/시스템 |
|----------|-----------|--------------|--------------|-------------|
| **EU (MDR Art.87)** | 중대 이상사례 | 인지 후 **10일** (심각 위협 시 2일) | 최종보고: 조치 완료 후 | EUDAMED MIR v7.3.1 |
| **FDA (21 CFR 806)** | Correction/Removal | 조치 개시 후 **10 영업일** | Supplemental Report | MedWatch 3500A / eMDR |
| **FDA (21 CFR 803)** | MDR (개별 이상사례) | 인지 후 **30일** (긴급 시 5일) | 추가 정보 입수 시 | MedWatch 3500A / eMDR |
| **MFDS** | 이상사례·회수 | 인지 후 **15일** | 회수종료 보고 | 의료기기안심책방(emedi) |

#### 5.7.2 IMDRF NCAR 양식 활용

- 다수 관할권 동시 보고 시 **IMDRF National Competent Authority Report(NCAR)** 양식을 기본 데이터셋으로 활용하여 정보 일관성을 확보한다.
- NCAR 데이터를 각 규제기관별 양식(MIR, MedWatch, emedi)에 매핑하여 전환한다.
- RA/QA Lead는 각 관할권 보고 기한을 FSCA Plan(F-FSCA-001)에 명시하고, 가장 빠른 기한에 맞추어 보고 일정을 역산한다.

#### 5.7.3 보고 진행 추적

- 각 규제기관별 보고 상태(초기보고 완료/후속보고 진행/최종보고 완료)를 F-FSCA-001에 기록·추적한다.
- 규제기관 질의(Query) 수신 시 해당 관할권 RA 담당자가 기한 내 회신한다.

### 5.8 FSCA 효과성 검증 (Effectiveness Check)

FSCA 완료 후 조치의 실효성을 체계적으로 검증한다.

#### 5.8.1 리콜 완료율(Recall Completion Rate) 목표

- **목표**: 영향 받는 기기 대비 조치 완료율 **≥ 95%**
- 완료율 = (조치 완료 기기 수 / 영향 대상 기기 총 수) × 100%
- 95% 미달 시 추가 사용자 연락, FSN 재배포, 규제기관 보고 등 후속 조치 실행

#### 5.8.2 추적 일정

| 시점 | 활동 | 산출물 |
|------|------|--------|
| **FSCA 개시 후 30일** | 1차 중간 점검: 조치 완료율 확인, 미조치 기기 파악 및 독촉 | 중간보고서 (F-FSCA-001 갱신) |
| **FSCA 개시 후 60일** | 2차 중간 점검: 완료율 재확인, 미조치 원인 분석, 대안 조치 검토 | 중간보고서 갱신 |
| **FSCA 개시 후 90일** | 최종 효과성 평가: 목표 달성 여부 판정, 잔여 미조치 기기 처리 방안 확정 | 효과성 검증 보고서 |

#### 5.8.3 효과성 미달 시 에스컬레이션

- 90일 시점에서 완료율 < 95%인 경우:
  1. 경영대표에게 보고하고 추가 자원 배정 요청
  2. 규제기관에 후속 보고(Supplemental Report) 제출
  3. 필요 시 Advisory Notice 추가 배포 또는 FSCA 범위 재조정
  4. CAPA(SOP-CAPA-001)에 연계하여 근본원인 재분석

### 5.9 규제기관 최종 보고

1. 모든 현장 조치 완료 후, RA/QA Lead는 최종 보고서(Final Report) 작성
2. 포함 내용:
   - FSCA 요약 및 근본원인
   - 실행된 조치 및 완료율
   - 재발방지 대책 (CAPA 연계)
   - 잔류위험 재평가 결과
3. 해당 규제기관에 최종 보고 제출:
   - EU: EUDAMED Final Report
   - FDA: 806.10 Supplemental Report
   - MFDS: 회수종료 보고

### 5.10 유효성 확인 및 종결

1. FSCA 완료 후 3~6개월간 모니터링하여 유사 이상사례 재발 여부 확인
2. 유효성 확인 완료 시 CAPA 종결과 연계하여 FSCA 기록 종결
3. 경영검토(SOP-MR-001) 시 FSCA 실적 보고
