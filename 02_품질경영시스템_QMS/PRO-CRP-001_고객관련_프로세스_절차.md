# PRO-CRP-001 고객관련 프로세스 절차

> **버전**: v0.1 | **최종 갱신**: 2026-05-10 | **작성**: holee9-automation

---

## 1. 목적

의료기기(X-ray system / detector / SW)의 고객 요구사항을 체계적으로 결정·검토하고, 규제 요구사항을 포함한 제품 요구사항의 충족 능력을 확인하며, 고객·규제기관과의 효과적 의사소통 체계를 수립한다.

## 2. 적용 범위

- 제품 공급 계약·주문 접수·견적 발행 전 과정
- OEM/ODM 공급, 직접 판매, 유통업체 경유 판매
- 설치·교육·유지보수 서비스 계약
- 규제기관 요구사항 식별 및 의사소통

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 고객 | 제품·서비스를 수령하는 자 (병원, 유통업체, OEM 파트너, 최종 사용자) |
| 계약검토 | 주문·계약 수락 전 요구사항 충족 능력 확인 활동 |
| 제품 요구사항 | 고객 명시 요구 + 의도된 용도 묵시 요구 + 규제 요구 + 자사 추가 요구 |
| IFU | Instructions For Use — 사용설명서 |
| URS | User Requirement Specification — 사용자 요구사항 명세서 |

## 4. 책임과 권한

| 역할 | 책임 |
|------|------|
| 영업/사업개발 | 고객 요구사항 접수, 초기 실현 가능성 검토, 견적 발행 |
| RA/QA Lead | 규제 요구사항 식별, 적합성 판단, 인허가 필요 여부 확인 |
| R&D Lead | 기술적 실현 가능성 검토, 개발 일정·자원 산출 |
| 제조/생산 | 생산 능력·납기 검토 |
| 최고경영자 | 비표준 계약·고위험 프로젝트 최종 승인 |

## 5. 절차

### 5.1 제품 요구사항 결정 (§7.2.1)

고객과의 계약·주문 체결 전, 다음 요구사항을 빠짐없이 식별·문서화한다.

| # | 요구사항 유형 | 내용 | 예시 (X-ray 시스템) |
|---|-------------|------|-------------------|
| 1 | 고객 명시 요구 | 고객이 직접 지정한 사양·납기·수량·포장·인도 조건 | 병원 입찰규격서, 구매사양서 |
| 2 | 의도된 용도 묵시 요구 | 고객이 명시하지 않았으나 의도된 사용에 필요한 요구 | 진단영상 품질, 환자·술자 피폭 ALARA |
| 3 | 적용 규제 요구 | 대상 시장별 법규·표준·인허가 요구 | MFDS 허가, CE 마킹, FDA 510(k), IEC 60601-2-54 |
| 4 | 사용자 교육 요구 | 안전하고 효과적인 사용을 위한 교육·훈련 | 방사선 안전교육, SW 운용교육, IFU 제공 |
| 5 | 자사 추가 요구 | 자체 품질기준·브랜드 기준 등 | 자사 선량 기준(국제 DRL 대비 xx% 이하) |

#### X-ray 시스템 규제 요구사항 체크리스트

| 대상 시장 | 필수 확인 항목 |
|----------|--------------|
| 한국 (MFDS) | 의료기기 품목허가, GMP 적합인정, 진단용 방사선 안전관리규칙 적합, 디지털의료제품법 (SaMD 해당 시) |
| 미국 (FDA) | 510(k)/De Novo, QMSR 적합, Cybersecurity Premarket Submission, SBOM |
| 유럽 (EU) | CE 마킹, EU MDR 적합성 선언, NB 인증, EUDAMED 등록, EU AI Act (해당 시) |
| 공통 | IEC 60601-1, IEC 60601-2-54, IEC 62304, ISO 14971, IEC 62366-1 |

### 5.2 제품 요구사항 검토 — 계약검토 (§7.2.2)

#### 5.2.1 검토 시점

- 입찰 참여, 견적 제출, 주문 수락, 계약 체결 **전**
- 사양 변경 요청 접수 시

#### 5.2.2 검토 항목

| # | 검토 항목 | 확인 내용 |
|---|----------|----------|
| 1 | 요구사항 명확성 | 모호하거나 상충하는 요구사항이 해소되었는가 |
| 2 | 기술적 실현 가능성 | R&D가 요구 사양을 구현할 수 있는가 |
| 3 | 규제 충족 가능성 | 대상 시장 인허가를 취득할 수 있는가 |
| 4 | 생산 능력 | 요구 수량·납기를 충족할 수 있는가 |
| 5 | 변경 이력 | 이전 견적·계약 대비 변경사항이 식별·합의되었는가 |
| 6 | 서비스 요건 | 설치·교육·유지보수 범위가 합의되었는가 |

#### 5.2.3 검토 프로세스

```
[고객 요구 접수]
     │
     ▼
[요구사항 문서화] ── F-CRP-001 작성 ──→ [관련 부서 배포]
     │
     ▼
[부서별 검토]
  ├─ RA/QA: 규제 충족성
  ├─ R&D: 기술 실현성
  ├─ 생산: 제조 능력·납기
  └─ 영업: 상업 조건
     │
     ▼
[검토 결과 종합] ── F-CRP-001 완성
     │
     ├── 충족 가능 ──→ [계약/주문 수락] ──→ [설계 입력 연계]
     │
     ├── 조건부 충족 ──→ [고객과 협의·조건 합의] ──→ [재검토]
     │
     └── 충족 불가 ──→ [사유 문서화·고객 통지] ──→ [종결]
```

#### 5.2.4 승인 권한

| 계약 유형 | 승인 권한 |
|----------|----------|
| 표준 제품 주문 (카탈로그 사양) | 영업 부서장 |
| 커스텀 사양 (규격 변경) | R&D Lead + RA/QA Lead 공동 |
| 신규 시장 진출 (신규 인허가 필요) | 최고경영자 |
| OEM/ODM 개발 계약 | 최고경영자 |

### 5.3 요구사항 변경 관리

- 계약 체결 후 고객 또는 자사가 요구사항 변경을 요청하는 경우:
  1. 변경 내용을 F-CRP-001에 기록
  2. §5.2 계약검토를 재수행
  3. 설계·제조 영향 시 SOP-CC-001(변경통제) 연계
  4. 변경 합의 후 관련 부서·인원에게 변경 내용 통보
  5. 관련 문서(도면, BOM, IFU 등) 갱신 확인

### 5.4 고객 의사소통 (§7.2.3)

고객 및 규제기관과의 의사소통 채널을 수립하고 유지한다.

| # | 의사소통 유형 | 채널 | 책임 |
|---|-------------|------|------|
| 1 | 제품 정보 제공 | 카탈로그, 기술자료, IFU | 영업/마케팅 |
| 2 | 견적·계약·주문 처리 | 공식 서신, 이메일, 계약서 | 영업 |
| 3 | 고객 피드백 (불만 포함) | 불만접수 시스템, SOP-PMS-001 | QA/CS |
| 4 | 규제기관 의사소통 | 공식 서신, 전자민원, EUDAMED | RA |
| 5 | FSCA/리콜 통지 | 규제기관·고객 동시 통보 | RA/QA |
| 6 | 설치·교육 일정 | 서비스 계약서, 교육 안내서 | 서비스팀 |
| 7 | 자문 통지 (Advisory Notice) | EU MDR Art.89 경로 | RA |

#### 규제기관 의사소통 의무 (§7.2.3 b)

| 규제기관 | 의무 보고 사항 | 기한 |
|---------|--------------|------|
| MFDS | 부작용 보고, 리콜 보고, 제품결함 보고 | 15일/즉시(중대) |
| FDA | MDR (Medical Device Report), Recall | 30일/5일(중대) |
| EU NB/CA | Vigilance Report, FSCA, Trend Report | 15일/즉시(중대) |

### 5.5 입찰·제안 관리

| 단계 | 활동 | 산출물 |
|------|------|--------|
| 입찰 공고 검토 | 규격서 분석, 규제 요건 식별, Go/No-Go 판단 | 입찰검토서 |
| 기술 제안서 작성 | 제품 사양, 규제 적합성 근거, 서비스 계획 | 기술 제안서 |
| 견적·가격 산출 | 원가·마진·서비스 비용 산출 | 견적서 |
| 입찰 제출 | 입찰서류 패키지 | 입찰서 |
| 낙찰·계약 | 최종 계약 검토 → §5.2 계약검토 | 계약서, F-CRP-001 |
