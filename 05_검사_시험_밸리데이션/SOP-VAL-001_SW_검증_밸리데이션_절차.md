# SOP-VAL-001 소프트웨어 검증 및 밸리데이션 절차 v0.2

## 1. 목적

본 절차는 의료용 X-ray 시스템에 내장된 소프트웨어(영상 획득·처리·표시·AI/ML 모듈·사이버보안 기능 포함)의 검증(Verification) 및 밸리데이션(Validation) 활동 전반을 정의한다. IEC 62304에 따른 SW 안전 등급별 활동 수준을 명확히 하고, 각 단계의 입력·출력·판정 기준·책임을 구체화한다.

## 2. 적용 범위

- SW 안전 등급: Class B 이상 (X-ray 영상 시스템 SW는 피해 가능성이 있으므로 최소 Class B, 선량 제어 관련 모듈은 Class C)
- 대상 SW 항목(Software Item):

| SW 항목 | 안전 등급 | 근거 |
|---------|----------|------|
| 영상 획득 제어(Acquisition Controller) | Class C | 선량 제어 직접 관여 |
| 영상 처리 파이프라인(Image Processing) | Class B | 진단 영상 품질 영향 |
| 자동 노출 제어(AEC/ABC) | Class C | 환자 선량 직접 결정 |
| DICOM 통신 모듈 | Class B | 영상 데이터 무결성 |
| UI/UX 표시 모듈 | Class B | 진단 정보 표시 정확성 |
| AI/ML 추론 엔진 | Class B~C | 진단 보조 기능 수준에 따라 |
| 사이버보안 모듈(인증·감사로그·암호화) | Class B | IEC 81001-5-1 연계 |
| 시스템 안전 기능(인터록·경보) | Class C | 환자/운용자 안전 직결 |

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 검증(Verification) | SW 요구사항 대비 산출물의 정확성 확인 (IEC 62304 §5.5) |
| 밸리데이션(Validation) | 의도된 용도에 대한 적합성 확인 (ISO 13485:2016 §7.3.7 / IEC 62304 적용범위 밖 — §5.8은 Software release) |
| SW 단위(Software Unit) | 가장 작은 테스트 가능 SW 구성요소 |
| SW 통합(Integration) | SW 단위를 결합하여 상위 SW 항목으로 구성 |
| 회귀 시험(Regression Test) | 변경 후 기존 기능 영향 없음 확인 |
| SOUP | Software of Unknown Provenance (제3자 라이브러리) |
| SaMD | Software as a Medical Device |
| SBOM | Software Bill of Materials |
| OTS | Off-The-Shelf Software |
| V&V | Verification & Validation |

### 5.1 V&V 계획 (Verification & Validation Planning)

**담당**: SW Team Lead (작성) → RA/QA Lead (승인)
**시점**: SW 개발 착수 전 또는 SRS 승인 직후
**입력물**: SW 요구사항 명세서(SRS), SW 아키텍처 설계서(SDS), 위험분석서(SOP-RM-001)

V&V 계획서(**F-VAL-001**)에 다음을 문서화한다:

1. **시험 전략**: 단위 → 통합 → 시스템 → 밸리데이션 4단계 정의
2. **SW 안전 등급별 활동 수준**:
   | 활동 | Class A | Class B | Class C |
   |------|---------|---------|---------|
   | 단위 시험 | 해당 시 | 필수 | 필수 |
   | 코드 커버리지 | - | ≥80% 구문 | ≥90% 구문+분기 |
   | 정적 분석 | - | 권장 | 필수 (MISRA) |
   | 코드 리뷰 | - | 1인 이상 | 2인 이상 |
   | 통합 시험 | 해당 시 | 필수 | 필수 |
   | 시스템 시험 | 필수 | 필수 | 필수 |
   | 밸리데이션 | 필수 | 필수 | 필수 |

3. **합격 판정 기준(Pass/Fail Criteria)**: 각 단계별 진입/종료 기준
4. **시험 환경**: HW/SW/도구 구성 (§6 참조)
5. **SOUP 검증 방법**: SBOM 기반 (SOP-SBOM-001 연계)
6. **위험 기반 시험 우선순위**: 위험관리 파일의 위험 수준에 따른 시험 우선순위
7. **추적성 매트릭스 유지 계획**: F-VAL-003 양식 사용

**판정 기준**: RA/QA Lead 서명 완료 시 V&V 계획 확정

### 5.2 SW 단위 검증 (IEC 62304 §5.5)

**담당**: SW 개발자 (수행) → V&V Engineer (독립 검토)
**시점**: 각 SW 단위 코딩 완료 후
**입력물**: 소스코드, 단위 설계서, SW 요구사항

**Class C 필수 / Class B 필수 / Class A 해당 시:**

| 단계 | 활동 | 판정 기준 | 기록 |
|------|------|-----------|------|
| 2-1 | 단위 시험 케이스 작성 | 요구사항·설계 100% 추적 | F-VAL-003 |
| 2-2 | 단위 시험 실행 | 전 TC Pass | F-VAL-002 |
| 2-3 | 코드 커버리지 측정 | Class C ≥90% (구문+분기), Class B ≥80% (구문) | 도구 리포트 |
| 2-4 | 정적 분석 | MISRA C/C++ 위반 0건(Critical/Required) | 도구 리포트 |
| 2-5 | 코드 리뷰 | Class C: 2인, Class B: 1인 독립 리뷰 완료 | 리뷰 기록 |

**X-ray 시스템 특화 단위 시험 항목:**
- AEC/ABC 알고리즘: 다양한 팬텀 두께(5~30cm)별 선량 계산 정확도 ±5% 이내
- 영상 처리 파이프라인: 윈도우/레벨 변환, 엣지 강화, 노이즈 저감 각 모듈의 입출력 검증
- DICOM 인코딩: Pixel Data, Rescale Slope/Intercept, Window Center/Width 정확성
- 인터록 로직: 도어 센서, 콜리메이터 위치, 비상정지 입력 조합별 차단 동작
- AI 추론: 참조 데이터셋 대비 출력 재현성 (동일 입력 → 동일 출력)

**기록**: F-VAL-002 시험 결과 보고서

### 5.3 SW 통합 시험 (IEC 62304 §5.6)

**담당**: V&V Engineer (수행) → SW Team Lead (검토)
**시점**: 단위 검증 완료 후, 모듈 통합 빌드 생성 시
**입력물**: 통합 빌드, 인터페이스 명세서, SOUP 목록

| 단계 | 활동 | 판정 기준 |
|------|------|-----------|
| 3-1 | 모듈 간 인터페이스 시험 | 데이터 타입·범위·타이밍 사양 일치 |
| 3-2 | 데이터 흐름 정합성 | 영상 파이프라인 end-to-end 데이터 무결성 |
| 3-3 | DICOM 적합성 시험 | DICOM Validation Toolkit 합격 |
| 3-4 | SOUP 통합 확인 | SBOM 기재 버전과 실제 빌드 버전 일치 |
| 3-5 | AI/ML 모듈 ↔ 영상 파이프라인 인터페이스 | 추론 입력/출력 형식·범위 정합 |
| 3-6 | 사이버보안 모듈 통합 | 인증→권한→감사로그 흐름 정상 |

**X-ray 시스템 통합 시험 시나리오:**
- Acquisition Controller → Image Processing → DICOM Storage 전체 촬영 워크플로우
- AEC 센서 입력 → 선량 계산 → Generator 제어 신호 출력 타이밍 (≤100ms)
- 인터록 신호 → SW 차단 → UI 경고 표시 → 감사 로그 기록 전 체인
- 원격 서비스 VPN → 인증 → 진단 데이터 전송 → 세션 종료 전 흐름

### 5.4 SW 시스템 시험 (IEC 62304 §5.7)

**담당**: V&V Engineer + 사이버보안 담당 (수행) → RA/QA Lead (검토)
**시점**: 통합 시험 완료 후, 릴리스 후보 빌드 대상
**입력물**: SRS 전체, 위험관리 파일, 사이버보안 요구사항

| 단계 | 활동 | 판정 기준 |
|------|------|-----------|
| 4-1 | SRS 전수 대비 시스템 시험 | 모든 SRS 항목에 대해 TC 매핑, 전 TC Pass |
| 4-2 | 성능 시험 | 영상 처리 ≤ 사양 시간, 최대 환자 처리량 충족 |
| 4-3 | 부하·스트레스 시험 | 연속 촬영 100회, 대용량 DICOM 전송 안정 |
| 4-4 | 이상 조건 시험 | 네트워크 단절·디스크 풀·전원 중단 시 안전 상태 전이 |
| 4-5 | 사이버보안 시험 | SBOM 기반 CVE 점검, 침투 시험 (외부_Pen-test_계획서) |
| 4-6 | 사용적합성 시험 | IEC 62366-1 시뮬레이션 사용 환경 (형성적 평가) |
| 4-7 | 회귀 시험 | 변경 영향 범위 전수 재시험 |

**X-ray 시스템 시스템 시험 세부:**
- **선량 안전**: AEC 최대 선량 제한(fail-safe) — 설정 상한 초과 시 조사 자동 중단 확인
- **영상 품질**: 팬텀 영상 MTF, CNR, 균일도 측정 → QC-IQ-001 기준값과 비교
- **ALARA 기능**: 선량 표시(DAP), RDSR 전송, 가상 콜리메이션, 소아 프로토콜 동작
- **동시 접속**: 다중 워크스테이션에서 동시 영상 조회 시 데이터 무결성
- **긴급 상황**: 비상정지 → SW 상태 전이 → 재시작 후 데이터 복구 시나리오

### 5.5 SW 밸리데이션 (ISO 13485:2016 §7.3.7 — IEC 62304 적용범위 밖, §5.8은 Software release와 별개)

**담당**: V&V Engineer + 임상/사용적합성 담당 (수행) → RA/QA Lead (승인)
**시점**: 시스템 시험 완료 후, 릴리스 판정 전
**입력물**: 사용자 요구사항, 의도된 용도 정의서, 임상 시나리오

| 단계 | 활동 | 판정 기준 |
|------|------|-----------|
| 5-1 | 임상 환경 시뮬레이션 | 팬텀 사용 영상 품질이 진단 적합성 기준 충족 |
| 5-2 | 선량 정확도 밸리데이션 | AEC/ABC 출력 vs. 교정된 선량계 측정: ±10% 이내 |
| 5-3 | AI/ML 성능 밸리데이션 | 독립 데이터셋, 민감도/특이도/AUROC ≥ 사양 |
| 5-4 | 사용자 인터페이스 수용 시험 | 대표 사용자 5인 이상 태스크 완수율 ≥95% |
| 5-5 | 사용적합성 총괄 평가 | IEC 62366-1 §5.9 충족 |

**X-ray 밸리데이션 특화:**
- 촬영 모드: 성인 표준체형(20cm PMMA) + 소아 팬텀(10cm) + 비만 팬텀(30cm)에서 AEC 선량·화질 확인
- 투시 모드: 연속 5분 투시 시 선량률 안정성, 시간 경보(5분) 정상 동작
- DICOM 워크플로우: Worklist 수신 → 촬영 → PACS 전송 → 조회 전체 end-to-end (10 케이스)
- AI 모듈: 임상 의사 판독 결과 대비 일치율 평가 (해당 시)

### 5.6 SOUP 검증

**담당**: SW 개발자 (수행) → V&V Engineer (검토)

| 단계 | 활동 | 판정 기준 |
|------|------|-----------|
| 6-1 | SOUP 식별 목록 유지 | SBOM과 100% 일치 (SOP-SBOM-001) |
| 6-2 | 알려진 취약점 확인 | CVE/NVD 조회, Critical/High 0건 또는 완화 조치 문서화 |
| 6-3 | 기능·성능·안전 적합성 | 요구사항 대비 확인 완료 |
| 6-4 | SOUP 업데이트 시 회귀 시험 | 영향 범위 전수 Pass |

### 5.7 이상(Anomaly) 관리

1. 발견된 이상은 이상 추적 시스템에 즉시 기록
2. 심각도 분류:
   | 심각도 | 정의 | 처리 기한 |
   |--------|------|-----------|
   | Critical | 환자 안전 영향 (선량 오류, 인터록 실패) | 즉시 시정, 릴리스 차단 |
   | Major | 기능 장애 (영상 미표시, DICOM 전송 실패) | 릴리스 전 시정 |
   | Minor | 경미한 불편 (UI 표시 오류) | 차기 릴리스 시정 가능 |
3. 위험 평가 수행 (SOP-RM-001 연계)
4. 시정 조치 완료 후 재시험
5. 미해결 이상의 잔여위험 평가·문서화 → 릴리스 판정 시 검토

### 5.8 추적성 매트릭스

요구사항 → 설계 → 구현 → 시험 → 위험 간 양방향 추적성을 유지한다.

```
사용자 요구 ←→ SW 요구(SRS) ←→ 설계(SDS) ←→ 코드 ←→ 시험(TC) ←→ 위험(RM)
```

- **F-VAL-003** 추적성 매트릭스 양식 사용
- 변경 발생 시 SOP-CC-001에 따라 매트릭스 갱신
- 릴리스 판정 전 추적성 완전성(completeness) 검토: 누락 링크 0건

### 5.9 최종 V&V 보고서

SW Team Lead가 전체 V&V 결과를 종합하여 최종 보고서를 작성한다.

**포함 내용:**
- 각 단계별 시험 결과 요약 (Pass/Fail/Waived)
- 총 TC 수, Pass 수, Fail 수, 미해결 이상 수
- 미해결 이상의 잔여위험 수용 근거
- 추적성 매트릭스 완전성 확인
- V&V 계획 대비 이탈 사항 및 정당화

**판정**: RA/QA Lead 서명 → 릴리스 판정 회의 → SOP-CC-001 릴리스 절차
